# AI広報部のX下書き・承認フロー

最終検証日: 2026-08-09

## 要望 / ゴール / 背景

開発工程から作るX投稿案を、公開せずに下書きとして管理し、CEOが承認・修正依頼・却下を記録できるようにする。下書き内に個人情報または秘密情報を含めない。

## ユーザーストーリーと受け入れ条件

### US-22-1: 下書きの作成と安全な保存

As a AI広報部の担当者, I want X投稿案を下書きとして保存したい, so that 承認前に内容を確認できる。

Given: 機微情報を含まない投稿案がある
When: 担当者が下書きを保存する
Then: fake repository に `draft` 状態で保存され、投稿・外部送信は行われない

Given: メールアドレス、電話番号、APIキー、トークンまたはパスワードを含む投稿案がある
When: 担当者が下書きを保存する
Then: 保存せず、削除または置換を促す利用者向けメッセージを表示する

### US-22-2: CEOによる承認判断

As a CEO, I want 下書きに承認・修正依頼・却下の判断を保存したい, so that 公開せずに意思決定を追跡できる。

Given: 保存済みの下書きがある
When: CEOが承認、修正依頼、または却下を選ぶ
Then: fake repository にそれぞれ `approved`、`revision_requested`、`rejected` 状態として保存される

## 非ゴール

- X API、投稿ボタン、予約投稿、自動投稿、外部公開、分析API
- Supabase migration、`src/App.jsx`、既存パイプラインの変更
- 本Issue内でのSupabase等への実接続、認証情報設定、実在ユーザーの個人情報の取扱い

## リリース接続契約

local/fake repository は外部認証待ちでも開発を継続するための実装であり、初回リリースでは恒久的な代替ではない。初回リリース前に release-gate #31 で、Supabase等の承認済み認証必須サービスへ実接続し、同じ契約テストを通す。

実接続adapterは `create`、`list`、`requestRevision`、`approve`、`reject` の5操作、4状態、機微情報拒否の契約を維持する。接続停止時は local/fake repository へ戻せることも #31 の受入条件とする。本IssueのX投稿・外部公開禁止は、#31 の実接続後も維持する。
