# Kadode 反証・スクリーニング機能仕様 v0.1

## 目的

ユーザーの案を肯定する対話ではなく、構造化された反証・記録・決裁へ運びます。ai-company-osの判断基準書、graveyard、pipelineを実装仕様として継承します。

## ドメインモデル

`Idea`（所有者、ペイン一行、状態）→ `Proposal`（案）→ `Screening`（起案者と別実行ID、死因3件、根拠URL、判定）→ `DeepDive`（PEST/5F/TAM/SAM/SOM/競合/SWOT/反証）→ `ValidationPlan` → `DecisionRecord` → `Graduation`。

`GraveyardEntry`は表面的死因、根本原因（動機づけられた推論／チェックリスト後置／土地勘=勝ち筋の誤認／測りやすい軸の優先／新種）、再発防止文書を持ちます。

## 機械ゲート

- Stage 0: 10案、各案に誰の・何のペイン、必須条件1〜10・15の生成フィルタ。
- Stage 1: 起案実行IDと反証実行IDを分離し、相異なる根拠URL付きの死因3件。
- Stage 2: URL15件、定量根拠10件、競合3社、PEST/5F/TAM/SAM/SOM/SWOT/反証を必須。
- Stage 4: a〜eの決裁分類と理由を必須。無記入・「微妙」は未決裁。

## データ境界

アイデア本文と個人情報はユーザー所有。全量をMarkdown+JSONでエクスポートします。匿名死因統計の二次利用は独立したオプトインです。削除要求は即時削除を優先し、3年保存は既定値ではなく利用目的・撤回方法をUIで明示します。

## 非目標

融資・補助金申請の代理、法律判断、起業成功の保証、無人の連続実行、X自動投稿は扱いません。
