# MVP残作業の配送順

正本は `dots-implementation-master-plan.md`。これは完成条件を縮小せず、現在動いている変更を目的別に検査・配送するための分割案である。

## 基準と規律

- 基準main: `0294205a2f88`（PR #259）。PR #246–259の配送済み変更は再配送しない。安全注釈、明示的なClaim共有、Source系譜と改訂時の現行辺同期、概要のRun参照と保存時検証、内部の型付き関係経路、Neo4j改訂lock、memory Run一括保存はそれぞれ配送済みであり、下表の大きな単位全体が完了したという意味ではない。Neo4jの実同時更新確認とRun一括保存の永続実装は別の未完了条件である。
- live checkoutは `baf972b76ad8` を基点とする大量の未配送変更を持つ。`git diff origin/main` 全体をPRとして使わない。
- 各配送は基準mainから清潔なworktreeを作り、担当範囲だけ選別する。既存mainの新しい変更を古いlive版で上書きしない。
- 目安500行以内、単一目的、独立レビューと正確なmerge版での検査を通す。大きい項目はさらに分割する。
- 合成試験、通常ChatGPTの通し確認、main反映を別々に記録する。部分成功をMVP完成へ読み替えない。

## 配送とは別に残る完成条件

- 1回許諾された設備点検サービスの公開調査は既に終了。同じ結果のSource→Evidence→終端Run→8章概要→意味関係保存と別会話再利用も成功。修正後の実ChatGPT新規検索では関係の正式ID・状態・根拠IDも一致。新しい調査は始めず、mainへの正式保存・読取・投影配送と残る完成条件を閉じる。
- 代表5会話で根拠付きの再利用と訂正後の現行検索を確認する。合成5件の成功だけで代替しない。
- 正本プラグインのUSER/PRIVATE、組織本人Ownerのみ・招待なしは確認済み。workspace対応と別入口、スマホの書込拒否後の結果は引き続き確認する。
- 実画面のアイコン一致、通常保存先の同一ID維持、最終起動確認を行う。
- 正本の全受入完了後だけ不要な検証用登録を解除する。必要な依存接続・通常データ・復旧コピーは残す。
- `.orig`、未確認の証拠JSON、個人情報・秘密値、無関係な資産は配送しない。

Facet階層の追加などは、現行完成条件との対応を確認してから別配送にする。今回の分割案だけを理由に機能を追加したり、既存完成条件を除外したりしない。
