# Founder Graph 同姓同名候補の合成評価計画

最終更新: 2026-09-23
親計画: [`dots-implementation-master-plan.md`](dots-implementation-master-plan.md) の P4-SP-03

## 要望 / ゴール / 成功指標

要望は、名刺から保存した人物について、同じ人物かもしれない組合せを本人へ示し、確定前に二人を一人として扱わないことである。

ゴールは、外部AIや実在の連絡先を使わず、合成の人物データだけで候補の見逃しと誤った自動統合を数えられる基準を用意することである。

成功指標は、期待する同一人物組合せが候補上位3件以内に90%以上入り、自動統合が0件であることとする。

## ユーザーストーリーと受け入れ条件

### US-1 候補だけを見る

As a 単独利用者, I want 同姓同名や一致する連絡先を候補として見たい, so that 自分で同一人物かを判断できる。

Given: 同じ所有者に属する合成の人物が複数あり、氏名または連絡先の一致がある

When: 候補を作る

Then: 人物ID、候補になった理由、順位だけが返り、メールアドレス、電話番号、私的メモは返らない。

### US-2 自動で統合しない

As a 単独利用者, I want 候補表示だけでは保存済み人物が変わらないでほしい, so that 同姓同名の別人を失わない。

Given: 同一人物らしい合成の人物候補がある

When: 候補を作る

Then: 統合済みを表す関係、人物の削除、人物の状態変更は0件である。

### US-3 合成評価を再現する

As a 実装担当者, I want 合成データで候補品質を数えたい, so that 外部AIを接続する前に安全基準を固定できる。

Given: 正解の同一人物組合せを持つ合成データがある

When: 候補を上位3件まで評価する

Then: 再現率、期待組合せ数、発見数、自動統合数が決定的に返る。

- 人物または組織の自動統合。
- 実在の名刺、連絡先、会話文の使用。
- 外部AIへの連絡先送信。
- 統合確定画面、Neo4jへの統合書込み。
