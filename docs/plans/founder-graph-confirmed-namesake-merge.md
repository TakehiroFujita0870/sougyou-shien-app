# P4-03 本人確認済みの同姓同名統合 計画

最終更新: 2026-09-23

## 要望 / ゴール / 成功指標

要望は、同姓同名候補を自動で統合せず、本人の明示確認だけで二人の人物を統合することである。

ゴールは、ローカル合成データで、敗者を保管済みにし、勝者へ向かう確認済みの関係記録を一回だけ残せることとする。

成功指標は、確認入力なし、候補状態、所有者違い、人物以外の指定をすべて拒否し、同じ依頼の再送で記録を増やさないことである。

## ユーザーストーリーと受け入れ条件

### US-P4-03-1

As a 単独利用者, I want 二つの人物IDと自分の確認を指定して統合したい, so that 同姓同名の別人を自動で失わない。

Given: 同じ所有者の活動中の人物二人と確認根拠が保存されている

When: 勝者ID、敗者ID、`confirmed`、根拠ID、冪等キーを指定する

Then: 敗者だけが保管済みとなり、人物から人物への確認済み`MERGED_INTO`記録が一件作成される。

### US-P4-03-2

As a 単独利用者, I want 未確認候補を統合できないようにしたい, so that 候補表示が保存変更にならない。

Given: 同姓同名の候補が提案状態である

When: `confirmed`以外の確認値で統合を要求する

Then: 人物、関係記録、監査記録は変更されない。

### US-P4-03-3

As a 実装担当者, I want 同じ統合依頼を安全に再送したい, so that 通信再試行で統合記録が重複しない。

Given: 一度成功した統合依頼がある

When: 同じ入力と冪等キーを再送する

Then: 同じ記録IDが返り、再送として示され、追加の関係記録は作られない。

## スコープ外

- 自動統合、候補からの自動確定、画面操作。
- 外部AI、実在の連絡先、連絡先値の返却。
- Neo4jへの統合書込み。未対応時は明示的に拒否する。
- 勝者への既存関係の付替えと検索のリダイレクト。
