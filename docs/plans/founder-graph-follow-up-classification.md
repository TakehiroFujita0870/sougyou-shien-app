# Founder Graph 追加質問の処理区分 計画

最終検証日: 2026-09-23

## 要望 / ゴール / 成功指標

要望: P6-02の接続前に、二回目の外部調査、既存材料だけで行うレポート再編集、通信の再試行を混同しないローカル契約を追加する。

ゴール: 呼び出し側が意図を明示すると、保存の前に「新しい調査記録」「新しいレポート版」「同じ調査記録の通信再試行」のいずれか一つを決定できるようにする。

成功指標: 三つの意図が決定的に別の処理として返り、未指定または不正な意図は保存や外部通信を起こさず拒否される。

## ユーザーストーリーと受け入れ条件

### US-FUC-01 新しい調査を分ける

As a 単独Founder, I want 新しい外部調査を前回の調査と分けたい, so that 入力と結論を後から比較できる。

Given: 前回の調査記録と、その入力内容の要約がある。

When: 呼び出し側が「新しい外部調査」を指定する。

Then: 新しい調査記録を作る処理、前回を親にする処理、入力内容を新しく固定する処理が返る。

### US-FUC-02 レポートだけを更新する

As a 単独Founder, I want 新しい外部調査をせずにレポートだけを再編集したい, so that 根拠を増やさず説明を直せる。

Given: 前版のレポートがある。

When: 呼び出し側が「レポート再編集」を指定する。

Then: 新しいレポート版を作り前版を親にする処理が返り、新しい調査記録は作らない。

### US-FUC-03 通信失敗を同じ調査に残す

As a 単独Founder, I want 通信だけの失敗を同じ調査記録に残したい, so that 一時的な失敗で比較対象が増えない。

Given: 終了していない調査記録がある。

When: 呼び出し側が「通信再試行」を指定する。

Then: 同じ調査記録へ試行履歴を足す処理が返り、新しい調査記録もレポート版も作らない。
