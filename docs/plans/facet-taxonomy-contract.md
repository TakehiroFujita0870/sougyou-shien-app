# 根拠付き分類と実階層の契約

対象: 残実装計画F-1/F-2。画面のアセット一覧にカテゴリー見出しを追加するものではない。

分類語は独立したFacetとして保存し、Idea/Assetの所属とFacet同士の抽象→具体の関係を根拠付きのRelationAssertionとして扱う。複数所属は許すが自己参照と循環を拒否する。提案中は現在の根拠付き検索へ混ぜず、推定と確定を区別する。

## 原子的な階層書込み

- Facet同士のCLASSIFIED_ASを許す変更は、同じ配送で循環ガードと書込みロックを導入する。
- 訂正は同じ関係系列の現在版を置き換えてから階層を検査し、旧版と新しい版の両方を有効な分類として数えない。
- メモリは保存ロック内、Neo4jは所有者単位の分類系列ロックと同じ取引内で検査する。失敗時は循環する関係を保存しない。
- 既存の所有者・端点・Evidence・共有・関係改訂の検査を維持する。

受入検査: 循環、自己参照、他の所有者、訂正、撤回、現在系列の絞込みをテストする。操作公開・領域検索・画面の実経路表示は後続の配送で実装する。

戻し方: 操作公開前はコードを戻せる。分類データを保存し始めた後は保存データを消さず、書込みと読取りを一緒に戻す。既存の本人データ、鍵、索引を削除しない。

## 抽象分類からの読み取り

分類の検索は、他の記録を除いた後に件数制限を適用する。分類領域の取得は共有可能な現行分類・記録・関係・根拠だけを使用する。非公開の中間分類を経由する経路は公開しない。根拠の一部だけを落として関係を返さない。

広い分類から中間分類を経て記録に達する実際の経路を、各段階の識別子・名称・深さとともに返す。複数分類への所属を許容し、画面上のアセットに分類操作を要求しない。

受け入れ条件は、共有範囲と所有者の分離、古い記録の除外、件数制限前の分類絞込み、中間段階を保持した経路、複数所属の専用テスト成功。書込みやデータ移行は行わず、読み取り処理の変更単位を取り消せる。

## 会話からの分類保存

同じChatGPTから分類語の保存、記録への分類付け、上位・下位分類の根拠付き関係保存を呼び出せるようにする。既定はローカル専用。未知の入力は拒否し、所有者・再送・訂正の期待版・循環検査は既存保存契約へ委譲する。

アイデアの新しい分類は現行概要と章への参照を必要とする。訂正時に両参照を省略した場合だけ旧関係から引き継ぎ、片側だけの指定は拒否する。確認済み関係を自動訂正しない。受け入れ条件は操作一覧・厳密入力・既定共有範囲・再送・循環拒否・訂正の専用検査成功。操作公開を戻す場合も保存データは消さない。
