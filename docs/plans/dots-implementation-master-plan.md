# Dots. 実装全体計画

## 位置づけと現在地

Dots. は本人一人が使う創業専用の知識グラフである。製品の境界は[製品方針](founder-graph-pivot.md)、現行の保存形式は[データモデル](founder-graph-data-model.md)、反映と検証の状態は[現況](../operations/dots-current-status.json)および現行コードを正本とする。本書は次の未達条件と実装順を定める。完了した画面改修の詳細はGitとPR履歴に残す。

要望: 「レポートはMarkdown一本化」「Dots様式の章立て」「リンク・画像・Mermaid」「サクッと調査して蓄積」「保存後に意味グラフを整理」「CodexのLuna定期タスクは補助」「出典ノードの一クリックで新タブを開く」。

ゴール: ChatGPTで調べながらアイデアを小刻みに蓄積し、Dots. のレポートと意味グラフが失われずに育ち、別会話で出典付きの過去案・資産を再利用できる。

成功指標: 下記の全受け入れ条件を、合成データの自動試験と通常保存先の限定的な実機確認で満たす。性能比較はモデルまたは検索方式を変更する場合だけ行う。

現状の確認済み差分:

- `save_idea_brief` でMarkdown本文を省略して更新すると、最新版の本文が空になる。画面は最新版だけを表示する。過去版の物理削除は確認されていない。
- MCPにはMarkdown付きのIdeaBriefと、章別本文を別のReportVersionに保存する`save_research_report`が併存する。後者の公開章IDは文字列、保存先は整数を要求する。
- 保存後の意味関係登録はChatGPTへの手順であり、保存成功から完了までの処理待ち・再試行をDots.が保持しない。現行のNeo4j契約は、過去調査取り込みの概要からアイデアの意味関係を作れない。
- Markdownのリンク・公開HTTPS画像・Mermaid表示は画面側にある。グラフの出典ノード投影にはURLがなく、クリックは選択だけを行う。

## 利用者が得る流れ

1. ChatGPTでアイデアを話すと下書きが保存され、既存の案・資産・資料を検索できる。調査の許可や完成稿は下書き保存の条件にしない。
2. 通常の公開情報を調べるたびに、気づき、出典URL、確認済みか推測かを追記できる。Deep Research規模のフル調査は、従来どおり範囲と試行について本人の許諾を得る。
3. 人が読むレポートはMarkdownを正本とし、Dots様式の8見出しで育てる。途中段階では未記入の章を許す。調査済みの完成稿では8章、実際に参照した資料名・URL、事実と推論の区別を確認する。
4. レポートの更新は不変の版を追加する。部分追記や本文を省いた保存で旧本文を消さない。古い結論が現行案と合わない場合は旧版と明示し、隠さず履歴から読めるようにする。
5. 保存成功と同時に意味グラフの整理を処理待ちへ入れる。Dots.が最新版の内容と既存記録を照合し、根拠を示せる関係だけを保存する。失敗は状態として残して再試行する。
6. CodexのLuna定期タスクは未処理・失敗分の点検と再試行だけを担う。会話直後の反映を定期タスク待ちにはしない。
7. PCのグラフ画面で出典ノードをクリックすると、検証済みの公開URLを新しいタブで開く。

## Dots様式のMarkdown

完成稿の見出しは次の名称をこの順に置く。画面に章番号を表示しない。

1. エグゼクティブサマリー
2. ビジネスモデル
3. 顧客とマーケットサイズ
4. 収益モデル
5. 競争優位性
6. 実現可能性
7. リスク・撤退ライン
8. リスクミニマムなロードマップ

Markdown本文を唯一の人向けレポート原稿とする。章位置と資料URLは本文から抽出し、確認したClaim・Evidence、意味関係、改訂状態を該当箇所へ結び付けて保持する。ChatGPTには同じ章本文を別欄へ再入力させない。単なるURLの保存はその主張の検証完了を意味しない。外部の事実、本人の判断、AIの推論、未確認事項を区別する。

リンクは安全なHTTP(S)に限定し、画像は公開HTTPSのみ表示する。任意HTMLを実行しない。Mermaidは厳格な安全設定で描画し、失敗時は原文を残す。画像を表示するとブラウザーが配信元へ通信するため、秘密付きURLと非公開画像は受け付けない。

## ユーザーストーリーと受け入れ条件

### US-1 途中保存

As a Dots.の本人利用者, I want 調査中の発見を小刻みに保存する, so that 根拠の整理を待たずに考えを蓄積できる。
Given: 未調査の案と短い発見、公開HTTP(S) URLがある。
When: ChatGPTから発見とURLを複数回追記し、同じidempotency keyで保存要求を再送する。
Then: 発見とURLがMarkdownへ順序を保って一度だけ保存され、全8章の入力なしで下書きを読み戻せる。URLの保存だけでは主張を検証済みと扱わない。

### US-2 Markdown正本

As a Dots.の本人利用者, I want 一つのMarkdownレポートを育てる, so that 表・リンク・図・公開画像を含む評価を読み直せる。
Given: 部分的なMarkdown下書きと参照した公開資料があり、完成稿に8つの正規見出しが順番どおり含まれる。
When: ChatGPTから完成稿を保存し、再起動後にホームで開く。
Then: 8見出しの完成稿が本文の正本として欠落せず表示され、リンクが開き、表・許可された画像・Mermaidが描画される。章別本文の二重入力を要求しない。

### US-3 消えない改訂

As a Dots.の本人利用者, I want 概要の一部を直しても既存レポートを失わない, so that 途中の判断を安心して更新できる。
Given: Markdown本文のある案に複数の保存版がある。
When: 本文を指定せずに案を更新する、明示的に本文を置き換える、または古い版を読む。
Then: 省略時に本文は消えず、明示的な置換だけが新しい本文版となり、旧版へ戻って読める。内容が変わって旧調査が現行に適さない場合は旧版と表示する。

### US-4 意味関係の登録

As a Dots.の本人利用者, I want 保存した案と資産の関係が自動整理される, so that 点と線を指定せず次の検討に使える。
Given: 下書きまたは過去調査取り込みの現行概要と、関連候補の案・資産がある。
When: 内容を保存し、整理が完了する。
Then: 支持箇所を示せる関係だけが現行グラフに現れ、外部事実に関する推論は出典根拠を持つ。候補だけの関係は候補と表示され、改訂で古くなった関係は現行検索から外れる。

### US-5 故障からの復帰

As a Dots.の本人利用者, I want グラフ整理だけ失敗してもレポートを保つ, so that 調査をやり直さずに済む。
Given: レポート保存後にグラフ整理が途中で失敗する。
When: サービスの再開または再試行が行われる。
Then: レポートは一版のまま残り、処理状態が分かり、最新版だけが重複なく再処理される。Codexの定期点検は未処理・失敗分だけを対象にする。

### US-6 出典へ移動

As a Dots.の本人利用者, I want グラフの出典をクリックして元資料を開く, so that 関係の根拠をすぐ確かめられる。
Given: 公開URLのある出典ノードと、URLのない別種のノードがある。
When: 出典ノードを一回クリックする。
Then: 安全なURLだけが新しいタブで開き、元のグラフは残る。他のノードの選択動作は変わらない。

### US-7 別会話での再利用

As a Dots.の本人利用者, I want 過去案と資産の関係を別会話で取り出す, so that 同じ問答を繰り返さず新しい案を考えられる。
Given: 出典付きの案、資産、現行の意味関係が通常保存先にある。
When: 新しいChatGPT会話から関連する課題を検索する。
Then: 現行案、関係の種類、根拠、元のURL、推測か確認済みかが返り、旧版の関係は現行結果に混ざらない。

## スコープ外

- ChatGPT全会話の無断収集、Dots独自の調査実行器、独自の調査通知。
- スマートフォン向け管理画面。本人のスマートフォンでの閲覧はバックエンド安定後の別工程とし、現行のPC画面監査は1280×720とする。
- 外部画像の自動収集、著作権の自動判定、任意HTMLの実行、秘密付きURLの表示。
- 人物の自動名寄せ確定、既存の実データの一括削除、検索モデルの変更、通常の速度比較。
- 複数利用者、公開マーケット配布、課金、PDF・DOCX製本。

## 安全・復旧・検証の境界

- 通常保存先へ変更する前に対象の版・処理待ち・関係を読取確認し、復旧用コピーを確保する。旧版と出典を消さず、移行後の読戻しで同一性を確認する。
- 複数のツール呼出が途中で止まっても、レポート保存の成否とグラフ整理の成否を別に示す。再送は同じ成果を二重作成しない。
- 非公開メモ、連絡先、住所を既定でChatGPTや外部調査へ出さない。公開画像・URLの表示にも既存の安全制限を適用する。
- 変更範囲のbackend試験、frontend試験、ビルド、CI、PC 1280×720の直接確認を行う。未検証の実ChatGPT動作を合成試験で代用して完了とは呼ばない。
- 各PRは現行コードとの差分、受け入れ条件、影響、戻し方を記す。必須検査が落ちたまま次工程へ進まない。通常保存先の削除、人物名寄せ、外部公開は本計画で許可しない。
