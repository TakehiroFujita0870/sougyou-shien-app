# Dots. 実装全体計画

## 正本と範囲

Dots. は本人一人が使う創業専用の知識グラフである。製品の目的と利用体験は[製品方針](founder-graph-pivot.md)、保存単位と関係の契約は[データモデル](founder-graph-data-model.md)を正本とする。実装・稼働・検証の現在地は[現況](../operations/dots-current-status.json)と現行コードを照合する。完了した画面改善・内部整理の経緯はGitとPR履歴で確認する。

この文書は新しい作業台帳ではない。以下の完成条件を満たしたかを現況と実機で確認し、未達の条件だけを実装する。すでに通った検査を、変更や再発なしに繰り返さない。

## 利用者が得る結果

1. PCでもスマートフォンでも、本人のChatGPTから正本の「Dots」を選び、アイデアや資産を保存・検索できる。別会話やPC再起動後も同じ記録に到達する。現行のDots.画面はPC用とし、スマートフォンからの閲覧はバックエンド安定後の別工程とする。
2. 調査前のアイデアは下書きとして保存・検索できる。ChatGPTは具体的な未調査案を保存または再利用した際に一度だけ調査を提案する。外部を含むフル調査は、目的・範囲・試行予算について本人の許諾を得てから始める。
3. 調査結果から洗練した概要を作り、8観点の評価、資料の題名とURL、根拠、推測と確認済みの区別を残す。出典を保存するときに意味上のノード・関係も整理し、グラフ更新の追加承諾は要求しない。人物の同一性確認や破壊的変更は別に扱う。
4. 検索は文章の近さだけでなく、顧客課題、提供価値、能力、資産、過去案などの意味関係と根拠を使う。履歴・版管理の接続を事業上の関係と混同しない。訂正された古い関係は現行結果から外し、履歴は残す。
5. PCのホームは「アイデア」「あなたのアセット」「人的ネットワーク」のタブ、別にグラフとサービス管理を持つ。アセットは「強み・経験」「弱み・迷い」の2列で示し、個別に編集できる。人的ネットワークの詳細入力は将来の対象とする。グラフは意味関係を主役にし、保存形式の内部ノードを通常表示しない。
6. Windowsへのログイン後に保存先、画面、ChatGPT接続が依存順に起動する。画面を閉じても保存先は動き、サービス管理から状態確認と停止・再開ができる。停止中は接続不可でよい。

## 完成の確認

- ChatGPTから保存した記録が通常のNeo4jに存在し、別会話と再起動後の検索で同じ記録を取得できる。
- 調査前の下書きは未調査と表示され、調査許可を保存の条件にしない。調査済み表示は実際の調査完了と対応する。
- 実際の調査で使った公開情報のURLと資料名が概要からたどれる。URLのない外部調査を「出典保存済み」と扱わない。
- 意味関係には端点、種類、根拠、推測・確認状態、元になった概要の版がある。別会話で関連する案・資産と根拠を再利用できる。再送で重複せず、訂正後に旧関係が現行検索へ混ざらない。
- 非公開メモや連絡先を既定でChatGPTへ返さず、本人用の接続・固定所有者・ローカル画面の境界を維持する。接続の公開範囲を「本人だけ」と断定する前に、その設定と実際の権限を照合する。
- 1280×720のPC画面で、各タブ、グラフ、サービス管理、編集・削除、画面遷移を確認する。スマートフォン版管理画面の監査は行わない。
- 強み・経験と弱み・迷いを区別して保存・検索でき、後者が強みとして表示・再利用されない。既存の記録は強み・経験に残し、弱み・迷いは編集・削除できる。同じ懸念は次の会話で検索してから問い直す。
- 変更範囲に応じたテスト、ビルド、CI、実際の起動確認を行い、未検証の部分を完了と呼ばない。性能比較は検索モデル等を変更する特別な理由がある場合に限る。

## 実装の進め方

1. 現行コード、差分、[現況](../operations/dots-current-status.json)、この完成条件を照合して、未達だけを選ぶ。古い個別計画の「未着手」を現在の残件へ繰り上げない。
2. 一つの利用者価値または一つの障害に範囲を絞り、再現または受け入れ条件を定めて変更する。データ・認証・APIに影響する変更では既存データと戻し方を確認する。
3. 該当範囲の自動検査と必要な実機確認を終え、意味単位で正式版へ反映する。現況には新たな未達・解消・検証結果だけを簡潔に反映し、過去のPRやテスト件数を増殖させない。

旧時代の多利用者・課金・独立AI画面・PDF/DOCX製本、および完了した小計画は現在の実装対象ではない。削除した文書はGitから復元できるが、通常の検索対象には戻さない。

## 将来候補: 本人のスマートフォンからの閲覧

状態: バックエンドが安定した後に着手を判断する。今回は記録のみで、スマートフォン画面や外部接続は変更しない。PC向けの標準監査は引き続き1280×720とする。

As a Dots.の本人利用者, I want 自分のスマートフォンからアイデア・アセット・調査レポートを読む, so that PCを開かずに蓄積した内容を確認できる。
Given: PC側のDots.が稼働し、本人のスマートフォンが許可された私有ネットワークへ接続している。
When: スマートフォンのブラウザーでDots.を開く。
Then: 保存済みのアイデア・アセット・調査レポートを閲覧でき、記録編集・削除・サービス停止の操作は表示も実行もできない。許可していない端末と公開インターネットからは開けない。PCが停止中は閲覧できない。

初期案はTailscale Serve経由の閲覧専用画面とする。既存の`localhost:8765`画面は接続元・接続先の制限と管理操作を持つため、そのまま転送しない。着手時に本人のスマートフォンの接続可否、私有ネットワークの許可範囲、公開設定、再起動後の復帰、実機での可読性を確認する。Neo4j、内部API、ChatGPT接続口を直接公開しない。公開インターネット向けの接続方式とスマートフォンでの編集は対象外とする。

## 今回の画面・グラフ表示改修

要望: 記録の見え方を日本語中心にし、意味のない英字ノードを通常のグラフから外す。ホームとサービス管理の操作・状態表示を簡潔にする。

As a Dots.の利用者, I want グラフ上の意味ある記録と関係を日本語で読む, so that 保存形式を解読せず内容を理解できる。
Given: 根拠・概要版を含むグラフが保存されている。
When: グラフ画面を開く。
Then: 内部管理用の記録は通常表示されず、表示対象の名称と関係の説明は日本語になる。保存時の型名・識別子は変わらない。

### US-UI-2
As a Dots.の利用者, I want 記録の編集・削除・復元を必要なときだけ見る, so that 一覧を読みやすくできる。
Given: ホームと削除済み一覧に記録がある。
When: 記録へマウスを重ねる、または操作へキーボードで移動する。
Then: 枠線のない操作が現れ、マウスもキーボードも従来通り操作できる。

### US-UI-3
As a Dots.の利用者, I want 調査と稼働の状態を一目で判別する, so that 記録や接続の状態を迷わず把握できる。
Given: 調査前・調査後の案と稼働中・停止中のサービスがある。
When: ホームとサービス管理を見る。
Then: 案の右上は「調査済み」「未調査」のみを表示し、各サービスの稼働中には緑、停止中には赤の点を状態名の左に表示する。色に加えて状態名も残る。

### US-UI-4
As a Dots.の利用者, I want 画面の重なりを減らし、停止を慎重に実行する, so that 見やすく誤停止もしない。
Given: アセット一覧とサービス管理が表示されている。
When: 一覧を読む、またはDots.を停止する。
Then: 同色の枠を重ねた構成を解消し、停止ボタンは赤く、押した後の確認を経なければ停止しない。

### US-UI-5
As a Dots.の利用者, I want 選択したアイデアの詳細画面で編集・削除する, so that 一覧を操作部品で埋めず内容を確認しながら直せる。
Given: アイデアに題名、説明、調査概要と保存履歴がある。
When: 詳細右上の鉛筆またはゴミ箱を押す。
Then: 鉛筆では題名・説明を競合検出付きの新しい版として保存する。題名のみの修正は調査概要を引き継ぐが、説明を変えた場合、旧調査は履歴に残しつつ新しい案の現行調査と誤認させない。ゴミ箱では確認後に削除する。左の一覧には操作部品を置かない。

### US-UI-6
As a Dots.の利用者, I want 報告の見出しと本文を明瞭に読む, so that 長い評価を迷わず追える。
Given: 8観点の概要がある。
When: アイデア詳細を読む。
Then: 見出しの連番を表示せず、見出しと本文には識別可能な文字の強さと十分な明度差がある。

## アイデア詳細のMarkdown表示

要望: ChatGPTが作ったMarkdownレポートを一つの版としてDots.へ渡し、図・公開画像・表・リンクを含む内容を広い詳細欄で読む。左の一覧は題名だけにする。グラフ上の分類選択は外す。
ゴール: 調査結果を画面側で組み直さず、保存されたレポートを安全に読みやすく表示する。
成功指標: 下記の受け入れ条件を満たし、1280×720の稼働画面で確認できる。

### US-UI-7
As a Dots.の利用者, I want 調査レポートを広い詳細欄で読む, so that 長文と図を追いやすい。
Given: 未調査案と調査済み案、出典付きMarkdownレポートがある。
When: ホームで案を選ぶ。
Then: 左には題名だけが並び、右には右寄せの「未調査」または「調査済み」バッジ、読みやすい出典リンク、保存したMarkdownの表・公開画像・図が表示される。旧版の案は従来の8観点表示へ戻る。

### US-UI-8
As a Dots.の利用者, I want ChatGPTからレポート全文を一度に保存する, so that 図表を含む原稿を失わない。
Given: 対象の案と8観点・出典IDがある。
When: ChatGPTが既存の概要保存操作でMarkdown全文を渡す。
Then: 8観点と全文は同じ版に保存され、同じ再試行は重複せず、異なる全文での再試行は衝突として扱われる。共有可の全文だけがChatGPTへ返る。

### US-UI-9
As a Dots.の利用者, I want グラフ自体に集中する, so that 意味が不明な選択欄に迷わない。
Given: グラフが表示されている。
When: グラフ画面を開く。
Then: 「分類から探す」と「全体の意味グラフ」の選択欄はなく、立体グラフのスクロール操作は残る。

## 調査レポート保存後の意味グラフ登録

要望: ChatGPTで完成した調査レポートを全文保存し、その内容と実在する出典を根拠に、利用者が点や線を指示せずに知識グラフを更新する。
ゴール: 完成した調査を次の会話でレポートとして読め、関連する案・資産を根拠付きの意味関係から再利用できる。

### US-MCP-REPORT-1
As a Dots.の利用者, I want 完成した調査レポートを欠落なく保存する, so that 後で図表や出典を含めて読み直せる。
Given: 許諾済み調査の完了記録、8観点、現行の共有可能な出典根拠がある。
When: ChatGPTが調査済み概要を保存する。
Then: 空でないMarkdown全文がない保存は書き込み前に拒否される。全文、8観点、根拠IDは同じ版に保存され、再取得できる。未調査の下書きは全文なしでも保存できる。

### US-MCP-REPORT-2
As a Dots.の利用者, I want 保存したレポートから意味関係を自動整理する, so that 次の会話で自分の資産と案を掛け合わせられる。
Given: レポート全文の保存結果と、関係を支える現行の出典根拠がある。
When: ChatGPTが保存済みの最新版を読み戻す。
Then: ChatGPTは既存の案・資産・分類語を照合し、根拠のある関係・分類だけを保存する。案を含む関係には最新版概要IDと該当章を渡す。根拠がない候補や履歴だけを表す線は作らず、登録結果を読み戻して確認する。失敗時はレポート保存の成否とグラフ整理の成否を分けて伝える。

- すべてのレポートへ写真や図を強制すること、出典や数値の創作、既存の調査済み版の一括書き換え、Dots独自の調査実行器。
