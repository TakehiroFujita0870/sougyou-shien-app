# 稼働中Dotsを正式版へ統合する計画
最終検証日: 2026-09-27

## 要望 / ゴール / 成功指標
要望: 「いったん稼働中の成果を、正式版へまとめるところだけやって。」
ゴール: 稼働版の既存機能をmainへ配送し、新しいmainの保存契約・安全検査・進捗規約を維持する。
成功指標: 現行画面・制御・検索・MCPの結線を含む正式版で検査が成功し、通常Neo4j・秘密設定・稼働サービス・利用者の未コミット変更は変更しない。

## ユーザーストーリーと受け入れ条件
### US-INTEGRATE-01
As a 本人, I want 手元で動く成果を正式版から再現したい, so that 整理のために同じ機能を作り直さない。
Given: 稼働版は旧基点と未コミット変更、mainは後続の保存・根拠・進捗改善を持つ。
When: main基準の隔離作業場所で稼働版の追加差分を結合する。
Then: mainの後続契約とテストが残り、既存のローカル画面・制御・検索・接続の検査が成功する。
### US-INTEGRATE-02
As a 本人, I want 統合中も記録と接続を守りたい, so that 手元の作業や利用データを失わない。
Given: 通常Dotsは稼働中で、WindowsとWSLの作業差分がある。
When: 対象ファイルだけを隔離して検査・commit・push・review・mergeする。
Then: 通常DB、認証ファイル、稼働サービス、対象外差分に変更がなく、main反映と稼働反映を別々に報告する。

## 質問リスト
なし。今回の対象は既存成果の統合であり、新機能の判断を求めない。

## スコープ外
- 新しい外部調査・Deep Research、会話機能の追加、プロフィール表示の改造、意味分類の新規生成。
- 通常DB移行、削除・復元試験、速度比較、Windows再起動要求、稼働サービスの再配置。
- 無断の別タスク作成・復帰。旧main専用の新しい実装をliveで上書きすること。
- 検証用登録の解除と旧資産の一括削除。利用者の許可は受領済みだが、本統合へ混在させず対象を確定して別単位で実施する。

## ADR
作業所有権: rootは画面・起動定義・main.py・依存・文書・Git配送、内部core担当はNeo4j検索・schema・facet・runtime、内部local担当はローカル画面のbackendとMCP結線を所有する。MCPをcore担当からlocal担当へ移し、同じファイルの同時編集を避ける。両担当はcommitせず、rootが全体検査と配送を行う。

| 判断 | 選択と理由 | 却下案と理由 | 結果 |
| --- | --- | --- | --- |
| 統合の基準 | main 12d089b672a2に差分を結合 | live全置換では後続PRの分割・安全契約を失う | main専用ファイルは保持 |
| 配送単位 | 検索、制御、画面を小単位で検査・レビューし、統合目的の配送としてまとめる | 過去成果を500行ごとに機械的に切ると未結線版とCI待ちを増やす | 大差分の理由と目的別内訳をレビューに明示。新機能の同梱なし |
| 利用者訂正 | アセット表示は利用者確認済み。内部名の欠落から表示不足を推定しない | 旧報告を修正案件にして機能追加する案は今回の依頼と異なる | 誤認した残課題は撤回 |
| 既決モデル設定の記録 | 主会話の「これ以降のサブエージェントは、GPT-6 LunaのMediumにリーズニングエフォートを落としましょう」をDots内の例外へ反映。検索は「Embeddingとリランカー…マルチリンガルなモデル…Sentence Transformer」と「Lunaでリランクする…現実的じゃない」の指示を保持 | 古いmain規約へ戻すと利用者の後続指定と稼働版に矛盾 | 新規モデル選定・比較・ダウンロードは実施せず、全社の基本条文は変更しない |
