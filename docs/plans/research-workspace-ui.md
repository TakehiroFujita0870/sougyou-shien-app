# 横断調査ワークスペース UI 計画
最終検証日: 2026-08-09

## 要望 / ゴール / 成功指標
要望: 既存の調査オーケストレーター契約とローカル fake を使い、横断調査の入力・実行結果・部分失敗・根拠を確認できる画面を追加する。
ゴール: 利用者が送信先を選択し、ローカルの結果から原典位置と AI 推論を区別して読めるようにする。
成功指標: PC とスマホの Storybook story、単体テスト、Vite build、Storybook build が成功する。

## ユーザーストーリーと受け入れ条件
### US-1
As a 起業準備者, I want 調査対象を選んで論点を入力する, so that 横断調査の範囲を自分で確認できる。
Given: 調査画面を開いている
When: Web、JPO、ファイル、過去判断を選び論点を入力して実行する
Then: 選んだ送信先と論点を含むローカル実行結果が画面に表示される。

### US-2
As a 起業準備者, I want ソースごとの進行と失敗理由を読む, so that 取得済みの根拠を捨てずに次の操作を判断できる。
Given: 一部ソースが timeout または daily limit の実行結果がある
When: 結果を確認する
Then: 完了と失敗がソース名ごとに表示され、失敗理由と再試行操作が観測できる。

### US-3
As a 起業準備者, I want 根拠の位置と AI 推論を分けて確認する, so that 主張の確からしさを判断できる。
Given: URL、特許公開番号、ファイルページ、意思決定 ID を含む結果がある
When: 根拠一覧を確認する
Then: 各根拠に locator と種別が表示され、AI 推論には「AI推論」ラベルが表示される。

## ADR
| 判断 | 選択と理由 | 却下案と理由 | 結果 |
| --- | --- | --- | --- |
| データ境界 | React の注入可能な local fake を採用し、既存 API payload の source_status/evidence を画面用に再現する。資格情報や外部送信を含まないため。 | 実 API を直結する案は認証・外部送信の承認がなく、画面検証範囲を越えるため却下。 | 実 API 導入時に repository adapter を追加できる。 |
| 根拠表示 | locator を URL、特許公開番号、文書ページ、判断 ID としてテキスト表示し、AI 生成文を別カードにする。 | 根拠と推論を同じ本文に混在させる案は出典追跡ができないため却下。 | 根拠の確認可能性を維持する。 |
