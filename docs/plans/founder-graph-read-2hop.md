# Founder Graph 2段階検索と根拠投影 計画

最終検証日: 2026-09-23
状態: 実装前

## 要望 / ゴール / 成功指標

要望は、検索語に直接一致しないが関係をたどると再利用価値があるノードを、最大2段階まで候補に含め、関係の根拠IDを失わずに返すことである。

ゴールは、in-memoryとNeo4jの検索結果が同じ経路形式を持ち、owner境界と外部投影境界を維持したまま、MCPが根拠IDを返せる状態である。

成功指標は、合成グラフで直接一致、1段階先、2段階先の順にスコアが下がり、3段階先が含まれず、local_onlyノード・項目・根拠がMCP応答へ出ないことである。

## ユーザーストーリーと受け入れ条件

### US-1 関係を2段階までたどる

As a 単独利用者, I want 関係でつながる過去の資産を2段階まで検索したい, so that 表現が違う過去の知識も再利用できる。

Given: 直接一致ノードから1段階、2段階、3段階の関係先が同じownerで保存されている
When: 検索語で直接一致ノードを検索する
Then: 直接一致、1段階先、2段階先だけが結果に入り、スコアは探索距離に応じて低くなる

### US-2 根拠経路を保持する

As a 単独利用者, I want 検索結果から関係と根拠IDを追跡したい, so that AIの候補を事実と混同しない。

Given: 関係にEvidence IDが登録されている
When: 関係経由の検索結果を受け取る
Then: 結果はノードID、関係名、根拠IDを対応付けて返す

### US-3 外部投影を安全にする

As a 単独利用者, I want local_onlyのノードと項目をMCPへ出したくない, so that ローカルの人脈情報を守れる。

Given: 経路上にshareableとlocal_onlyのノードまたは根拠が混在している
When: MCPのsearchを実行する
Then: local_onlyのノード、項目、根拠IDは応答に含まれず、shareableな経路だけが返る

## ADR

| 判断 | 選択と理由 | 却下案と理由 | 結果 |
| --- | --- | --- | --- |
| 経路形式 | `(node, relation, node, ...)`の交互配列にする。既存の1段階形式と後方互換で2段階へ拡張できるため | 構造化objectへ直ちに変更する案は既存MCP利用者の読み替えが必要なため却下 | 1段階は3要素、2段階は5要素で返す |
| 探索上限 | 最大2段階を固定する。応答時間と説明可能性をboundedに保つため | 無制限探索は循環と大量結果を招くため却下 | 深さ3以上は候補に含めない |
| 根拠投影 | 根拠ノードがshareableの場合だけEvidence IDを返す。IDもownerとegress境界を持つため | IDを無条件に返す案はlocal_only資料の存在を推測できるため却下 | MCPは安全な根拠IDだけ返す |
