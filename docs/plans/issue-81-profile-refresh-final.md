# Issue #81 プロフィール再読込の修正計画

最終検証日: 2026-08-09

## 目的

保存済みプロフィールをアプリ起動時に一度だけ読み込み、完了済みユーザーを初回ヒアリングへ戻さない。読込失敗時は空データを保存させず、再試行できるようにする。

## 受け入れ条件

- Given 完了済みプロフィールがある、When アプリを再読込する、Then ダイアログを表示せず「あなたの情報を更新」を表示する。
- Given 未保存または途中保存、When 読込が完了する、Then 空または保存済み回答からヒアリングを開始する。
- Given 読込に失敗する、When エラー画面を表示する、Then 入力フォームと保存操作を出さず再試行だけを提供する。
- Given 親画面が再描画される、When 同じrepositoryを利用する、Then 初期読込回数は増えない。

## ADR

プロフィールの読込状態はAppが所有し、子フォームは親から渡された初期値と同じrepositoryだけを使う。親子で別々に読み込む案は、完了状態の不一致と再読込ループを生むため採用しない。

## スコープ外

プラン・モデル、Googleサインイン、旧アイデア下書き、資料、調査結果の永続化は別Issueとする。Supabase接続や外部送信は行わない。
