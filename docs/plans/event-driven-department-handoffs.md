# 部門間イベント駆動連携 計画
最終検証日: 2026-08-09

## 要望 / ゴール / 成功指標

要望: 定期実行ではなく、部門が作業イベントを相互通知して次工程を起動し、会話コンテキスト圧縮後も連携規則が残るようにする。

ゴール: PRの作成者、統合部、管理タスクの送信責任と応答責任をリポジトリ正本で固定する。

成功指標: `AGENTS.md`から運用正本へ到達でき、PR作成からレビュー、差し戻し、再レビュー、マージまでの各イベントに送信者、受信者、必須項目、停止条件がある。

## ユーザーストーリーと受け入れ条件

### US-1
As a 実装部門, I want PR作成時に統合部を直接起動したい, so that 定期監視を待たずレビューを開始できる。

Given: 実装部門がPRを作成またはhead SHAを更新した
When: 実装部門が `PR_READY` を送る
Then: 統合部は通知されたhead SHAをレビュー対象として受領する

### US-2
As a 統合部門, I want レビュー結果を担当部へ直接返したい, so that 修正またはマージ後処理が次のturnで開始される。

Given: 統合部が通知されたhead SHAのレビューを完了した
When: 統合部が判定する
Then: 担当部へ `REVIEW_CHANGES_REQUESTED`、`MERGED`、`BLOCKED` のいずれかを送る

### US-3
As a 新しく起動したエージェント, I want 会話履歴なしで連携規則を復元したい, so that コンテキスト圧縮後も通知が失われない。

Given: エージェントがリポジトリ作業を開始した
When: `AGENTS.md`と運用正本を読む
Then: 送信責任、応答責任、必須payload、停止条件を特定できる

## ADR

| 判断 | 選択と理由 | 却下案と理由 | 結果 |
| --- | --- | --- | --- |
| 起動方式 | タスク間メッセージによるイベント駆動。作業完了直後に次工程を起動できる | 定期ポーリングは遅延と重複レビューを生む。会話内だけの口頭規則は圧縮で失われる | AGENTS.mdから運用正本を必読にする |
| 永続化場所 | リポジトリのAGENTS.mdとoperations文書。全エージェントが開始時に読める | 特定タスクのプロンプトだけでは別タスクと再起動後へ伝播しない | Git履歴で変更をレビュー可能にする |
| 代替経路 | PRコメントへ非機密payloadを残し管理タスクへ通知 | 無限再送は重複作業を生む | 送信不能をBLOCKEDとして可視化する |
