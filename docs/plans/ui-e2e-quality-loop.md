# UI E2E品質ループ 計画

最終検証日: 2026-08-09

## 要望 / ゴール / 成功指標

要望: 最新mainの実UIをPC幅と390px幅で監査し、初回訪問からプロフィール、AI対話、事業のタネ保存、再読込までのhappy pathをE2E化する。

ゴール: local/fake境界の主要導線が端末内保存だけで再現でき、再読込後もプロフィールと事業のタネを確認できることを自動検証する。

成功指標: 1280pxと390pxの両方で同一シナリオが成功し、network requestが発生せず、PIIをfixtureへ含めない。

## ユーザーストーリーと受け入れ条件

### US-E2E-1

As a 初回訪問者, I want プロフィールを入力してAI対話を始めたい, so that 自分の前提を反映した事業のタネを作れる。

Given: localStorageが空の1280pxまたは390pxの画面を開く
When: プロフィール6項目を入力して完了し、対話で発言を送る
Then: プロフィールダイアログが閉じ、会話履歴と保存前プレビューが表示される。

### US-E2E-2

As a 利用者, I want 対話から事業のタネを保存して再読込したい, so that 作業を中断しても候補を失わない。

Given: 対話の保存前プレビューが表示されている
When: 「アイデア候補として保存」を押して1280pxまたは390pxでAppを再マウントする
Then: 保存済みの候補名と概要が再読込後に表示される。

### US-E2E-3

As a 390pxの利用者, I want モバイルメニューの対象を支援技術から把握したい, so that サイドバーの開閉を迷わず操作できる。

Given: 390px幅でモバイルメニューを表示する
When: メニューボタンのアクセシブルな関係を確認する
Then: メニューボタンの`aria-controls`がサイドバーのIDを指す。

## スコープ外

- #89の認証、Google sign-in、owner state、redirect、cookie、token。
- 既存のIdeaCandidateWorkspaceの入力・保存ロジック変更。
- 外部API、network送信、Supabase、実ブラウザへの個人情報送信。
- 追加で観測した摩擦の実装（Issue下書きに記録する）。

## 摩擦のIssue下書き

- 初回プロフィール6項目の入力負荷は別Issueで段階保存を検討する。
- 長い会話履歴のスクロール体験は別Issueで検討する。
