# MVPワークスペース統合 計画
最終検証日: 2026-08-09

## 要望 / ゴール / 成功指標
要望: mainへマージ済みのプロフィール、アイデア仮説、資料庫、横断調査、モデル選択、AI広報下書きを通常アプリURLのワークスペースに統合する。

ゴール: 利用者がPCまたはスマホの同じアプリ画面から主要なMVP領域を開き、ローカル動作の境界を確認できる状態にする。

成功指標: 静的レンダリングテストで全ナビゲーション項目、初回プロフィール優先表示、外部未接続表示を観測でき、キーボードでナビゲーションを切り替えられる。

## ユーザーストーリーと受け入れ条件
### US-1
As a 起業準備者, I want 主要なワークスペースを一つのアプリから選ぶ, so that 作業目的ごとに画面を探さずに済む。

Given: 通常アプリURLをPCまたはスマホで開いている
When: ナビゲーションのアイデア、横断調査、資料、設定、AI広報を選択する
Then: 選択した領域の見出しと既存コンポーネントが表示される

### US-2
As a 初回利用者, I want プロフィール入力を先に始める, so that 後のアイデア整理に自分の情報を使える。

Given: プロフィールが未完了である
When: アプリを開く
Then: あなたの情報ダイアログが表示され、閉じた後もナビゲーションのプロフィール操作で再表示できる

### US-3
As a キーボード利用者, I want ナビゲーションをキーボードで操作する, so that ポインティングデバイスなしでも領域を切り替えられる。

Given: PCでワークスペースを開いている
When: ナビゲーション項目へTabで移動してEnterまたはSpaceを押す
Then: フォーカス表示が見え、選択領域が切り替わり、現在地がaria-currentで示される

### US-4
As a プライバシーを気にする利用者, I want local/fake動作を識別する, so that 外部送信が起きないことを確認できる。

Given: 横断調査、資料、モデル選択、AI広報のいずれかを開いている
When: 説明文を確認する
Then: 外部サービス未接続または外部送信しない旨が表示され、外部APIを呼ぶ実装が追加されない

## ADR
| 判断 | 選択と理由 | 却下案と理由 | 結果 |
| --- | --- | --- | --- |
| 統合方式 | App内の状態ベース表示にする。既存Viteアプリへ依存を増やさず、通常URLで利用できる。 | ルーター導入は画面URLの要件が未確定で、差分が広がるため却下。 | App shellで選択領域のみを表示する。 |
| モバイルナビ | 横スクロール可能なbutton群にする。全領域を同じ意味で操作できる。 | ハンバーガーメニューは開閉状態と追加のフォーカス管理が必要なため却下。 | flex横並びとoverflow-x-autoを使う。 |
| 外部未接続表示 | shellと各既存コンポーネントの既存メッセージを併用する。 | 実接続のモックは外部送信なしの境界を曖昧にするため却下。 | local/fakeの明示バナーを追加する。 |
