# Issue #69 アイデア入口統合 計画

最終検証日: 2026-08-09

## 要望 / ゴール / 成功指標

要望: アイデア入力の二重導線を解消し、Notion型の縦UI内で対話、仮説カードのプレビュー、明示保存を一つの主導線にする。巨大heroは表示しない。

ゴール: 利用者が着想を会話で整理し、保存前に生成元を確認した上で端末内の候補として保存できる。

成功指標: idea landingに旧3項目フォームと巨大heroを表示せず、PCとmobileのStoryおよび自動テストで対話、プレビュー、保存、再開を確認できる。

## ユーザーストーリーと受け入れ条件

### US-1

As a 起業を考え始めた利用者, I want 着想を一つの対話欄から話す, so that 同じ内容を複数フォームに入力しない。

Given: 事業のタネのlandingを開いている
When: 入力欄に着想を送り対話を進める
Then: 保存前プレビューが表示され、明示した保存操作でのみ候補になる。

### US-2

As a 再開する利用者, I want F5や低速読込後も未送信入力を守る, so that 考え途中の内容を失わない。

Given: 端末内の会話または旧3項目下書きがあり、読込が遅延している
When: 読込完了前に新しい入力を始める
Then: 新しい未送信入力は読込結果で上書きされず、旧下書きは会話へ移行できる。

### US-3

As a プライバシーを重視する利用者, I want ローカルだけで補完案を確認する, so that 外部送信なしで候補を作れる。

Given: 対話欄に着想を入力している
When: 補完案を要求する
Then: 決定的なローカル補完案だけをプレビューし、採用するまで原文を変更しない。

## UI情報構造

- #69: 「事業のタネ」ページはbreadcrumbの直下に簡潔なページ見出しを置き、会話、保存前プレビュー、保存済み候補を縦に読む。
- #69: 会話中の利用者発言だけから端末内で芽を検出し、保存前のカードを表示する。候補の保存と編集は明示操作に限る。
- 依存: 全ページ共通AI会話composer、desktop常設/即時展開、mobile固定入口、現在page/project contextは#74/#78に接続する別PRで扱う。#69はWorkspaceShellの構造・環境badge・共通libraryを変更しない。

| 判断 | 選択と理由 | 却下案と理由 | 結果 |
