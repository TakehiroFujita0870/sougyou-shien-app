ゴール: PC再起動後もChatGPTから普段のDots.へ安全に保存・検索でき、アイデアを8観点で履歴付きに育て、意味に基づく関連をたどり、検索・復旧・変更履歴を検証できる状態にする。

## 現状と停止線

- Windows再起動後、通常Neo4j、画面、読み取りサービス、通常ChatGPT接続用の中継は稼働し、画面は実DBから10点・5本を返した。2026-09-25、ChatGPTの新しい会話で通常Dotsを明示選択し、再起動前のIdeaと同じ記録IDを取得した。書込みは未実施。
- 合成Neo4j container自体は起動したが、ログオンtaskがDisabledで合成Tunnelは停止していた。検証のため一時起動すると中継healthは成功した一方、MCP検索は認証失敗で利用不可だった。合成containerのsecret mountは通常DBと同じWindows上の一時認証ファイルを指し、通常DBの認証交換後に合成DBの保存済みパスワードと一致しなくなった。合成Tunnelは試験後に再停止した。通常DBと通常接続には影響しない。合成DBとそのvolumeは消去しない。
- 通常接続はsmall/384次元/再順位付けOFF。base/768次元/40候補の構成は合成接続だけにある。モデルや検索経路の変更理由がない限り速度比較を再実施しない。
- ホームの8観点は先頭の概要を除き「未整理」。奥行き表示はノード種別による固定4段階で、意味に基づく分類ではない。
- 添付ファイル保存部品は存在するが、現行の通常接続には組み込まれておらず、通常用の添付保存先も構成されていない。現時点の通常記録はNeo4j内に保存される。将来この部品を有効化する前に、DBと添付物の同世代復旧を別途必須にする。
- 作業場所に多数の未コミット変更がある。所有範囲と秘密情報を確認するまで一括ステージ、既存変更の復元、main切替をしない。

## ユーザーストーリーと受け入れ条件

### US-MC-01 再起動後に使い続ける

As a Dots.の単独利用者, I want PCを再起動してもChatGPTから以前のアイデアを探し新しい記録を残したい, so that 起動操作を意識せず蓄積を続けられる。

Given: 再起動前に保存した共有可能な記録と、通常用・合成用の接続がある。
When: Windows再ログイン後、新しいChatGPT会話で通常接続から既存記録を検索し、合成接続で新しい架空Ideaを保存して別会話と画面から探す。
Then: 既存記録の同一ID、架空Ideaの保存IDと再取得、通常用と合成用の分離を確認できる。個人連絡先と非公開本文は返らない。失敗時は記録を重複投入せず原因を残す。

### US-MC-02 アイデアを8観点で改訂する

As a Dots.の単独利用者, I want 一つのアイデアを事業評価の8観点で育てたい, so that 調査が進んでも過去の考えと根拠を見失わない。

Given: 既存Ideaまたは新規の合成Ideaがある。
When: ChatGPTから8観点のうち一部を保存し、その後一観点を訂正する。
Then: 同じIdea IDに新しい版が追加され、旧版は変わらず、各観点の本文・根拠・未確定区分・更新理由を取得できる。空欄は「未整理」と表示される。

### US-MC-03 意味から具体例へ進む

As a Dots.の単独利用者, I want 抽象的な領域から関連するIdea・Asset・Person・Evidenceへ進みたい, so that 思いがけない組み合わせを発見できる。

Given: 同じ領域に属する合成IdeaとAsset、および属さない記録がある。
When: 領域を指定してグラフを開き、画面で奥へ進む。
Then: 領域との関係と根拠を持つ記録だけが段階的に現れ、単なる種類別表示と区別できる。分類候補は推測と明示され、自動で確定関係にはならない。

### US-MC-04 通常検索を安全に改善する

As a Dots.の単独利用者, I want 意味が近い過去案も固有名詞も検索したい, so that ChatGPTで発想を再利用できる。

Given: 合成用で評価済みの固定モデルと、通常用の現行索引がある。
When: 通常用とは別の索引に候補モデルの埋め込みを補完し、安全性・品質・資源上限を合成データで確認した後、通常用検索を切り替える。
Then: 結果に根拠と関係経路が残り、非公開情報の漏出0件、旧検索へ設定だけで戻せることを確認する。品質または資源の合格条件を満たさなければ通常用は現行設定を維持する。

### US-MC-05 復旧と変更履歴を信頼する

As a Dots.の単独利用者, I want 保存内容と開発変更を戻せるようにしたい, so that PC障害や開発上の失敗で創業の記録を失わない。

Given: 通常用データと多数の未コミット変更がある。
When: 読み取り専用で対象と変更所有者を照合し、同じ世代のデータと添付物の復旧用コピーを取得し、隔離先へ復元し、対象ファイルだけを意味単位でGitに反映する。
Then: 復元後のID・件数・代表検索が一致し、通常用データは変わらない。Git差分に秘密値・個人情報・他作業の変更がなく、検査とmainの動作確認を記録する。

### MC-03 スパイク結論: アイデアの8観点

現行`Idea.revise()`は新しいIdea IDを作って旧IDを`supersedes_id`で指し、画面は旧版を一覧から隠す。仕様書の「安定したIdea ID」と実装は一致しない。また`ReportVersion`は調査Runの成果物であり、アイデア概要そのものではない。既存のIdea IDを書き換える移行を先に行うと、保存済みの関係とChatGPTの参照を壊す危険がある。

採用する最小追加は、既存Ideaを変更せず、同じ着想の系譜に紐づく不変の`IdeaBriefVersion`を別に持つ方式とする。最初のIdea IDを系譜の根、現在のIdea IDを根拠にした版として記録し、8章の短い本文、章ごとのClaim/Evidence ID、未確定区分、変更理由、作成時刻を保持する。版番号は系譜内で一意にし、同時更新時は旧版を上書きせず競合を返す。画面は最新の版を各Ideaへ重ねて表示する。ChatGPTへの返却はIdeaと章ごとの共有設定の双方が許す範囲に限定する。旧Ideaと旧ReportVersionは読取互換を維持し、変更しない。

これによりMC-04は、(a) domain契約と失敗テスト、(b) Neo4jの追加制約・保存/再取得、(c) MCPの用途限定書込み、(d) ホームの表示、の4つの意味単位に分割する。各単位は先行単位が検査済みになるまで着手しない。

### MC-05 スパイク結論: 抽象から具体への探索

現行には再利用可能な`Facet`と、Idea/Asset/Person等からFacetへの`CLASSIFIED_AS`関係がある。これを使い、Facet同士に「広い分類→狭い分類」の関係を追加する。循環、別owner、根拠のない確定関係を拒否する。LLMの分類結果は最初は提案状態で保存し、確定済みの事実と画面上で区別する。探索はFacetを起点に、直接分類された記録と、その下位Facetに分類された記録だけを段階的に取得する。既存の種類別4段階表示は、Facetがまだ無い間の表示として残す。検索順位の関係展開は最大2 hopの既存安全境界を維持する。

これによりMC-06は、(a) relation契約・循環防止、(b) owner限定の読取口、(c) PC画面の領域選択と奥行き表示、の3つに分割する。

### MC-10 進捗: 通常DBの復旧用コピー

2026-09-26、通常用Neo4jだけを短時間停止し、`C:\Users\hp\founder-graph-backups\run-20260926-live-pre-idea-brief`にneo4j/systemの両dumpを取得して自動再開した。保存先は本人・SYSTEM・管理者だけが読める独立ディレクトリ。元DBはhealthyに戻り、ホームはIdea 5件を返した。read-onlyの代表3問と件数をmanifestに記録し、別の新規restore volumeへ両dumpを読み込み、復元後の件数と結果hash一致がPASS。復元したvolumeは調査のため保持し、通常volumeを変更しない。通常接続には添付ファイル保存部品がまだ配線されていないため、現行の通常記録についてMC-10のDB復旧試験は合格。添付物を使う段階では同世代の取得・復元を新しい受け入れ条件として再度確認する。
