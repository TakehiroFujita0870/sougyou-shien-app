# CI軽量化と旧資産整理 計画

最終更新: 2026-09-23
実行状態: 計画済み、CI軽量化を実装中

## 要望 / ゴール / 成功指標

要望は、個人開発の通常編集でGitHubの待ち時間が製品開発を止めないようにし、旧資産を安全に整理することである。

ゴールは、毎回の必須確認を本体の保存・検索・基本画面・ビルドに限定し、ブラウザ実演、見た目比較、PDF・DOCX全ページ確認を手動の節目確認へ分離することである。

成功指標は、必須ジョブが重い確認を起動せずに成功し、手動確認を明示的に起動でき、旧資産の削除候補と保留理由を一覧で追跡できることである。

## ユーザーストーリーと受け入れ条件

### US-1 通常編集を短時間で確認する

As a 単独開発者, I want 通常の変更で本体の安全確認だけを短時間で実行したい, so that Founder Graphの実装を止めずに進められる。

Given: pull requestまたはmainへの変更がある
When: 必須CIを起動する
Then: Nodeの基本テスト、ビルド、Pythonの基本テストが実行され、ブラウザ実演、Storybook、LibreOfficeは実行されない。

### US-2 節目に重い確認を実行する

As a 単独開発者, I want 画面または帳票を変更した節目に重い確認を手動で実行したい, so that 必要な証跡を残せる。

Given: GitHubのActions画面で手動確認を開始する
When: 全確認用workflowを実行する
Then: 既存のブラウザ、Storybook、PDF、DOCX、LibreOffice確認と証跡保存が実行される。

### US-3 旧資産を安全に整理する

As a 製品責任者, I want 旧資産の参照状況と削除理由を確認してから整理したい, so that 現行機能と復旧経路を壊さない。

Given: 旧資産候補の一覧と参照検索結果がある
When: 明らかに未使用の一群を整理する
Then: 関連テスト、仕様、復旧可能性を確認したうえで、意味単位の変更として削除または保留を記録する。

## スコープ外

- GitHubの必須確認名を変更すること。
- `docs/inherited/`を変更または削除すること。
- 旧資産を参照調査なしに一括削除すること。
- Dotsの保存、検索、Neo4j、MCPの仕様を変更すること。
- 夜間の定期実行を追加すること。

## ADR

| 判断 | 選択と理由 | 却下案と理由 | 結果 |
| --- | --- | --- | --- |
| 必須確認の範囲 | 本体テスト、ビルド、Pythonテストを常時実行する。製品の保存・検索に近く、main保護を維持できるため | 全確認を常時実行する案は個人開発の反復を遅くするため却下 | `quality`を短い必須確認として維持 |
| 重い確認の起動 | `workflow_dispatch`で手動開始する。画面・帳票の変更時だけ必要なため | 必須CIへ残す案は無関係な変更でも長時間待つため却下 | 節目確認へ移行 |
| 必須確認の起動条件 | 必須確認自体は全pull requestとmain反映で起動する。保護設定の未完了状態を防ぐため | 変更場所でworkflow全体を停止する案は必須結果が出ないため却下 | 内部stepの実行範囲を切替 |
| 旧資産の扱い | 参照一覧、保留理由、復旧経路を先に残す | 一括削除は現行経路と移行前データを壊す可能性があるため却下 | 一群ずつ整理 |
