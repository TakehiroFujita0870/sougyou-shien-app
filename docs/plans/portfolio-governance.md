# 全社ポートフォリオ管理・要件決定計画

最終検証日: 2026-08-09

## 要望 / ゴール / 成功指標

要望: CEO室を全社ポートフォリオ管理・要件決定へ拡張し、統合部のASSIGNMENT/WIP規約を壊さずにイベント駆動で運用する。

ゴール: CEO室は優先順位と例外判断に集中し、統合部がレビュー・配分・handoff、実装部が割当済み実装を担う。

成功指標: ORG_HEALTH、PORTFOLIO_DIRECTIVE、REQUIREMENT_REQUESTの送信境界、payload、冪等性、禁止用途が正本に記録される。

## ユーザーストーリーと受け入れ条件

### US-1 組織状態の観測

Given: merge後にnext_dependenciesが空かつidle部門と未割当ready Issueが同時にある、WIPが0または上限超、P0 BLOCKED、同一ファイル所有権競合、依存先未割当、またはCEO決裁境界が発生した
When: 統合部が状態を集計する
Then: 各部のactive/idle/WIP、review queue、未割当ready Issue、依存block、24時間内の停止リスクだけを含むORG_HEALTHをCEO室へ一度送る。

### US-2 ポートフォリオ指示の翻訳

Given: CEO室が優先順位、配分、WIP、停止/再開、または境界を決めた
When: PORTFOLIO_DIRECTIVEを統合部へ送る
Then: 統合部は実装部へ直接の実装指示を渡さず、ASSIGNMENTまたはDEPENDENCY_READYへ翻訳する。

### US-3 ユーザー要件の限定エスカレーション

Given: P0未決、複数部設計衝突、またはCEO決裁境界がある
When: CEO室がユーザー判断を必要とする
Then: REQUIREMENT_REQUESTには選択肢、推奨、未決時に止まる範囲を含める。通常のCI/P1/P2/進捗確認には送らない。

## スコープ外

- 定期ポーリング、常時監視ジョブ、外部サービス接続
- ASSIGNMENT、WIP制限、部門所有権の削除または緩和
- 実装部へのCEO室からの直接実装指示
