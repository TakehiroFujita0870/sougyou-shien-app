# 市場・競合・攻めどころレポート 計画

最終検証日: 2026-08-09

## 要望 / ゴール / 成功指標

### 要望原文

> 仮説カードから「市場の見込み」「競合との違い」「攻めどころの特定」を生成する。フレームワーク名を主要見出しに出さず、根拠、反対材料、未確認事項、カード更新案を分離する。更新はユーザー承認後に行う。

### ゴール

Evidence付き調査結果と過去判断を入力に、根拠と推論を区別した決定的なローカルレポートを返し、カード更新案の承認状態を所有者ごとに観測可能にする。

### 成功指標

- 同じ入力は同じ見出し・内容・更新案を返す。
- 反対材料または未確認事項を、根拠と混在させずに返す。
- 承認前の更新案は`proposed`、承認後は`approved`でAPIから観測できる。

## ユーザーストーリーと受け入れ条件

### US-1 レポートを読む

As a 仮説カードを検討するユーザー, I want 調査根拠と過去判断から市場・競合・攻めどころを読める, so that 次に検証する内容を判断できる。

Given: 一件以上のEvidenceまたは過去判断を入力している
When: ローカルレポートを生成する
Then: `市場の見込み`、`競合との違い`、`攻めどころの特定`を含み、根拠、反対材料、未確認事項、カード更新案を別フィールドで返す

### US-2 更新案を承認する

As a 仮説カードを編集するユーザー, I want 更新案を確認してから承認する, so that 根拠のない変更がカードへ反映されない。

Given: 本人のレポートに`proposed`のカード更新案がある
When: 更新案を承認する
Then: 同じレポート取得でカード更新案の状態が`approved`となり、承認日時が返る

### US-3 他者の更新案を見ない

As a 利用者, I want 自分の更新案だけを操作したい, so that 他者の意思決定を変更しない。

Given: 別の所有者が作成したレポートがある
When: そのレポートを取得または承認しようとする
Then: `market_report_not_found`を返す

## ADR

| 判断 | 選択と理由 | 却下案と理由 | 結果 |
| --- | --- | --- | --- |
| 入力境界 | Evidenceと過去判断を明示的なAPI入力にする。外部接続なしで生成契約を検証できる | 実検索runやDBへ直結する案は永続化接続と認証情報の決裁が未完了のため却下 | 実接続時は同じ入力モデルへadapterを接続する |
| 生成方式 | 固定ルールで入力を区分し、入力順を保つ。再現可能で説明できる | LLM生成は外部送信と費用の承認がないため却下 | 将来はモデルadapterの後段に置く |
| カード更新 | 提案と承認を別エンドポイントにする | 生成時に反映する案はユーザー確認要件に反するため却下 | 承認記録を返す |
