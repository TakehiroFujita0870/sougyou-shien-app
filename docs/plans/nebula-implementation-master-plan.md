## 位置づけと現在地

### US-29 整理対象の見落としと誤った資産関係を防ぐ

要望: 「Proceed your recommendation」。ゴールは、待ちジョブ0件を全体整理完了と誤認せず、資産更新後にも既存案を検討すること。
As a 本人利用者, I want 保存した案と資産の関係を漏れなく点検する, so that 同じ問答を繰り返さず保存内容を使える。
Given: 現行レポート、明示的空候補、期限切れ処理中ジョブ、弱みまたは判断基準がある。
When: 本人限定CLIで最大20件を点検し、ChatGPTで資産を保存する。
Then: 未登録ジョブと空候補を別状態で報告し、期限切れ処理中は自動再開せず要確認とする。弱みを再利用能力として登録する候補、判断基準を必要能力とする候補を拒否する。資産保存後は関連案を検索し、本文の根拠がある候補だけ保存する。
タスク: 既知—検証器の分類制約、期限切れleaseの読取点検。類推可能—現行レポートのジョブ対応と空候補の読取監査。旧経路で現行本文の根拠付き関係が保存済みなら、ジョブ欠落と意味関係未保存を混同せず、再登録しない。検査: owner・上限・旧版除外・本文非出力・手動関係済みの区別・分類拒否のテスト。
スコープ外: 無関係な線の追加、外部調査、テスト記録の削除、秘密や本文の出力、Codexや他アプリの設定変更。cmd.exeは実行元と登録済み起動設定の読取調査だけ行う。
ADR: 定期点検は未評価候補を推測生成せず、現在版との対応欠落を可視化する。空候補の成功を失敗へ書換えず、検索で関連なしと判断した場合と未点検を区別する。旧手動経路は関係family識別が異なるため、ジョブ補完を目的に同じ関係を新経路へ再登録しない。既存関係の件数を併記するだけで全体整理完了とは断言しない。期限切れleaseは既存許諾範囲を広げず要確認に留める。全孤立点への強制接続と無制限の全件再保存は却下する。

### US-28 孤立点を消さず関係を育て、判断基準を大きな星にする

要望: 「エッジつないでほしい」「判断基準のアセットだけは特に大きなノード」。
As a 本人利用者, I want 記録の根拠に基づくつながりと目立つ判断基準を見る, so that 案と自分の判断軸を一緒にたどれる。

When: 保存内容を照合して関係を追加し、グラフを開く。
Then: 判断基準の星は通常資産より大きく、根拠に結び付く提案関係が保存・再取得できる。既存の孤立点は削除されず、無関係な線は増えない。
タスク: 既知—資産分類の限定投影と大きさ・ラベル・当たり判定の検査。類推可能—現行レポートから最大20件の関係を既存の書込経路で追加し、同じ関係の重複と再取得を検査。PC1280×720で判断基準の大きさとクリックを確認する。
スコープ外: 新しい外部調査、内容の書換、記録の削除、架空の関係、根拠のない全点接続、個人情報の公開。
ADR: 分類は本文やタイトルから推測せず保存済み属性を使う。関係はレポート版へ紐付く提案として保存し、見た目だけの擬似エッジや一律のハブ接続を却下する。完了証拠は既存の現況とGit/PRに残す。

### US-27 丸みとアイボリーの共通意匠

検証: フロント検査・ビルド・文字コントラスト・実画面の横断監査。完了証拠はGit/PRを正本とする。

現行実装との照合結果:

- Markdown本文の保持、途中追記、保存後の処理待ち、出典ノードの安全な新規タブ表示、判断基準の蓄積、本人用接続は実装済み。現況と検証範囲は[現況](../operations/nebula-current-status.json)を参照する。

## 利用者が得る流れ

1. ChatGPTでアイデアを話すと下書きが保存され、既存の案・資産・資料を検索できる。調査の許可や完成稿は下書き保存の条件にしない。
2. 通常の公開情報を調べるたびに、気づき、出典URL、確認済みか推測かを追記できる。Deep Research規模のフル調査は、従来どおり範囲と試行について本人の許諾を得る。
3. 人が読むレポートはMarkdownを正本とし、Nebula様式の8見出しで育てる。途中段階では未記入の章を許す。調査済みの完成稿では8章、実際に参照した資料名・URL、事実と推論の区別を確認する。
4. レポートの更新は不変の版を追加する。部分追記や本文を省いた保存で旧本文を消さない。古い結論が現行案と合わない場合は旧版と明示し、隠さず履歴から読めるようにする。
5. 保存成功と同時に意味グラフの整理を処理待ちへ入れる。Nebulaが最新版の内容と既存記録を照合し、根拠を示せる関係だけを保存する。失敗は状態として残して再試行する。
6. CodexのLuna定期タスクは未処理・失敗分の点検と再試行だけを担う。会話直後の反映を定期タスク待ちにはしない。
7. PCのグラフ画面で出典ノードをクリックすると、検証済みの公開URLを新しいタブで開く。

## Nebula様式のMarkdown

完成稿の見出しは次の名称をこの順に置く。画面に章番号を表示しない。

各章は正確な見出し名をH1（`# タイトル`）またはH2（`## タイトル`）で一度ずつ書く。同じ文書でH1とH2を混在してよい。H3以上、重複、順不同の見出しは章投影に使わない。コードフェンス内の見出しも無視する。

1. エグゼクティブサマリー
2. ビジネスモデル
3. 顧客とマーケットサイズ
4. 収益モデル
5. 競争優位性
6. 実現可能性
7. リスク・撤退ライン
8. リスクミニマムなロードマップ

Markdown本文を唯一の人向けレポート原稿とする。章位置と資料URLは本文から抽出し、確認したClaim・Evidence、意味関係、改訂状態を該当箇所へ結び付けて保持する。ChatGPTには同じ章本文を別欄へ再入力させない。単なるURLの保存はその主張の検証完了を意味しない。外部の事実、本人の判断、AIの推論、未確認事項を区別する。

リンクは安全なHTTP(S)に限定し、画像は公開HTTPSのみ表示する。任意HTMLを実行しない。Mermaidは厳格な安全設定で描画し、失敗時は原文を残す。画像を表示するとブラウザーが配信元へ通信するため、秘密付きURLと非公開画像は受け付けない。

## ユーザーストーリーと受け入れ条件

### US-1 途中保存

As a Nebulaの本人利用者, I want 調査中の発見を小刻みに保存する, so that 根拠の整理を待たずに考えを蓄積できる。
Given: 未調査の案と短い発見、公開HTTP(S) URLがある。
When: ChatGPTから発見とURLを複数回追記し、同じidempotency keyで保存要求を再送する。
Then: 発見とURLがMarkdownへ順序を保って一度だけ保存され、全8章の入力なしで下書きを読み戻せる。URLの保存だけでは主張を検証済みと扱わない。

### US-2 Markdown正本

As a Nebulaの本人利用者, I want 一つのMarkdownレポートを育てる, so that 表・リンク・図・公開画像を含む評価を読み直せる。
Given: 部分的なMarkdown下書きと参照した公開資料があり、完成稿に8つの正規見出しが順番どおり含まれる。
When: ChatGPTから完成稿を保存し、再起動後にホームで開く。
Then: 8見出しの完成稿が本文の正本として欠落せず表示され、リンクが開き、表・許可された画像・Mermaidが描画される。章別本文の二重入力を要求しない。Markdownを指定した初回保存では`sections[].content`を省略または空にでき、Markdownなしの初回下書きでは少なくとも一観点に本文が必要。

### US-3 消えない改訂

As a Nebulaの本人利用者, I want 概要の一部を直しても既存レポートを失わない, so that 途中の判断を安心して更新できる。
Given: Markdown本文のある案に複数の保存版がある。
When: 本文を指定せずに案を更新する、明示的に本文を置き換える、または古い版を読む。
Then: 省略時に本文は消えず、明示的な置換だけが新しい本文版となり、旧版へ戻って読める。内容が変わって旧調査が現行に適さない場合は旧版と表示する。

### US-4 意味関係の登録

As a Nebulaの本人利用者, I want 保存した案と資産の関係が自動整理される, so that 点と線を指定せず次の検討に使える。
Given: 下書きまたは過去調査取り込みの現行概要と、関連候補の案・資産がある。
When: 内容を保存し、整理が完了する。
Then: 支持箇所を示せる関係だけが現行グラフに現れ、外部事実に関する推論は出典根拠を持つ。候補だけの関係は候補と表示され、改訂で古くなった関係は現行検索から外れる。

### US-5 故障からの復帰

As a Nebulaの本人利用者, I want グラフ整理だけ失敗してもレポートを保つ, so that 調査をやり直さずに済む。
Given: レポート保存後にグラフ整理が途中で失敗する。
When: サービスの再開または再試行が行われる。
Then: レポートは一版のまま残り、処理状態が分かり、最新版だけが重複なく再処理される。Codexの定期点検は未処理・失敗分だけを対象にする。

### US-6 出典へ移動

As a Nebulaの本人利用者, I want グラフの出典をクリックして元資料を開く, so that 関係の根拠をすぐ確かめられる。
Given: 公開URLのある出典ノードと、URLのない別種のノードがある。
When: 出典ノードを一回クリックする。
Then: 安全なURLだけが新しいタブで開き、元のグラフは残る。他のノードの選択動作は変わらない。

### US-7 別会話での再利用

As a Nebulaの本人利用者, I want 過去案と資産の関係を別会話で取り出す, so that 同じ問答を繰り返さず新しい案を考えられる。
Given: 出典付きの案、資産、現行の意味関係が通常保存先にある。
When: 新しいChatGPT会話から関連する課題を検索する。
Then: 現行案、関係の種類、根拠、元のURL、推測か確認済みかが返り、旧版の関係は現行結果に混ざらない。

### US-8 判断基準の蓄積

As a Nebulaの本人利用者, I want 強み・迷いと区別して判断基準を記録する, so that 別の事業案でも選択理由を再利用できる。
Given: 本人が会話で「規模より関係密度を優先する」と述べ、共有可能な短い記述として保存を求める。
When: ChatGPTが判断基準として登録し、Nebulaを再起動して検索する。
Then: 判断基準として一件だけ読み戻せ、既存の強み・迷いの内容と共有範囲は変わらない。個別案の決定結果と混同しない。

### US-9 三列のアセット一覧

As a Nebulaの本人利用者, I want 全アセットを追加順の三列一覧で見る, so that 分類をまたいで蓄積の全体を把握できる。
Given: 三分類の記録と、編集済みの古い記録がある。
When: PCの1280×720画面で一覧を開き、編集・分類変更・削除・キーボード移動を行う。
Then: 左から右、次の行へ追加順で並び、編集や分類変更では位置が動かない。各カードのバッジ、編集・削除、フォーカスと確認操作が使用できる。

### US-10 判断基準の再利用

As a Nebulaの本人利用者, I want 新しい案と関連する判断基準を見つける, so that 同じ優先順位の問答を繰り返さずに済む。
Given: 現行の判断基準と、それに関連する新しい事業案がある。
When: 別のChatGPT会話で案を検索・検討する。

### US-14 実際に行った調査の表示

## 安全・復旧・検証の境界

- 通常保存先へ変更する前に対象の版・処理待ち・関係を読取確認し、復旧用コピーを確保する。旧版と出典を消さず、移行後の読戻しで同一性を確認する。
- 複数のツール呼出が途中で止まっても、レポート保存の成否とグラフ整理の成否を別に示す。再送は同じ成果を二重作成しない。
- 非公開メモ、連絡先、住所を既定でChatGPTや外部調査へ出さない。公開画像・URLの表示にも既存の安全制限を適用する。
- 変更範囲のbackend試験、frontend試験、ビルド、CI、PC 1280×720の直接確認を行う。未検証の実ChatGPT動作を合成試験で代用して完了とは呼ばない。
- 各PRは現行コードとの差分、受け入れ条件、影響、戻し方を記す。必須検査が落ちたまま次工程へ進まない。通常保存先の削除、人物名寄せ、外部公開は本計画で許可しない。

## ゴールモードでの実行指示

このファイルをobjectiveとしてゴールモードを開始した場合、T-0からT-9を依存順に進める。開始時と各PRの後にmain・現況・実機を再照合し、未達だけを選ぶ。各工程で計画とコードが違えば、承認済み方針への適合を先に判断する。小さな意味単位ごとに検査、commit、push、PR、review、main反映、main smokeを閉じる。実データ本文と秘密は作業報告・PR・試験記録へ出さない。モデルが利用できない、既存データの移行先が不明、必須検査が失敗、または本人の新しい判断が不可欠になった場合は該当範囲を止め、証拠と選択肢を報告する。完了はUS-1からUS-7とT-9を満たしたときだけ宣言する。

## 表示改修: レポート・星空グラフ・アイデア一覧

要望: 「レポートはもう直しちゃって。スクロールの件も任せます」「グラフは既存ライブラリを出発点に、本当に星空に見えるUIにしてほしい」「全てのアイデアで、書式・表記・見せ方を統一する」。

ゴール: 保存済み本文に触れずに全アイデアの表示を統一し、長文レポートを読みやすくする。グラフは平面上の星の大きさで抽象から具体への違いを示す。

成功指標: PCの1280×720で全アイデアの題名・状態・章・出典・操作が共通規則に従い、長文レポートを一つの縦スクロールで読める。グラフは深度切替をなくして全ノードを同じ平面に描き、根拠確認と出典を開く操作を維持する。

### US-18 レポートの読書画面

As a Nebulaの本人利用者, I want 保存済みレポートを読みやすい画面で見る, so that 章と出典を追いながら内容を検討できる。
Given: 長文・表・画像・Mermaid・長い公開URLを含む既存のMarkdownレポートがある。
When: PCの1280×720でアイデア詳細を開いてスクロールする。
Then: レポート本文の保存値は不変で、外側だけが縦スクロールし、章・本文・引用・表を区別でき、公開リンクの行先と安全設定が維持される。

### US-19 星空グラフ

As a Nebulaの本人利用者, I want 点そのものを星として知識の広がりを見る, so that 抽象的な分類から具体的な記録まで直感的に探索できる。
Given: 分類の親子関係、アイデア、資産、出典、根拠付き関係が現行グラフにある。
When: PCの1280×720でグラフを開き、点と線を選択する。
Then: 4段階の深度表示と奥行き移動はなく、平面の星が分類の階層に応じた大きさで表示され、名称の衝突を抑えつつ点と線の操作、出典の新規タブ表示を維持する。階層不明の点に推測した大きさを付けない。常設の記録検索・意味関係一覧は置かず、通常時はグラフだけを表示する。点と線の選択時だけ詳細を表示する。初回の物理配置は画面に出す前に完了し、横長の描画領域に合わせて配置を広げ、光輪が見切れない余白を残した最大倍率で一度だけ収める。以後は選択・ドラッグ・スクロールで倍率や配置をリセットしない。

### US-20 全アイデアに共通する表示規則

As a Nebulaの本人利用者, I want どのアイデアも同じ見せ方で読む, so that 記録ごとの書式差に迷わず内容を比較できる。
Given: 現行の一覧にMarkdown本文、旧形式の章別本文、未調査の下書きが混在する。
When: 任意のアイデアを選択して詳細と出典を読む。
Then: 題名・調査状態・本文・見出し・出典・編集操作は共通の配置と文字規則で表示される。存在しない章・出典・調査結果は補わず、保存済み本文とリンク先は変えない。長文は一つの縦スクロールで読める。

### スコープ外

- レポート本文、保存形式、MCP入力、調査状態の再判定、データ移行は変更しない。
- スマートフォン用レイアウト、実データの削除、3Dと2Dの切替機能は追加しない。
- 個別アイデアの本文編集、旧記録の一括書換え、未調査案への架空の8章作成はしない。

### US-21 星の見た目と意味の読み取り

As a Nebulaの本人利用者, I want 星の群れから記録と関係を読める, so that 見た目だけでなく案と資産の共通点を探索できる。
Given: 現行の案・資産・出典と根拠付き関係がある。
When: PC 1280×720で通常表示、拡大、選択を行う。
Then: 暗い背景に記録そのものの光点と滑らかに薄れる淡い光を描く。種類ごとに光点の大きさを区別し、出典よりアセット、アセットより案、案より分類を大きくする。分類内の確定階層のサイズ差は維持する。色は恒星の黒体放射を参考にした淡い暖色・白・青白の範囲で種類を区別し、温度や重要度の実測値とは扱わない。十字の光条・星形の輪郭・鮮やかな色の円は使わない。案・分類の名称は衝突を避けて通常時から表示する。拡大時は他の名称も表示し、選択時は関連先と関係名を読める。初回倍率のリセットは再発せず、架空の飾りノードは追加しない。

### US-22 既存記録の関係整理

As a Nebulaの本人利用者, I want 既存の内容に基づく関係を補う, so that 過去の案と資産を再利用できる。
Given: 通常保存先の既存記録と現行Briefがある。
When: 既存の保存契約を通して関係候補を整理する。
Then: 本文・調査状態・共有範囲を変えず、現行Briefの根拠箇所に結び付く関係だけ追加する。推論は提案として区別し、出典の同一性だけで意味関係を断定しない。根拠なしの孤立ノードは残す。再送は重複せず、追加分は識別可能で取り消せる。根拠欄はMarkdownの章を既存の読取投影で表示し、曖昧な見出し・旧版・所有者不一致は表示しない。

### US-24 共通の背景

As a Nebulaの本人利用者, I want 全アイデアで同じ背景を見る, so that 切替で星の位置や大きさが変わらない。
Given: 長さの異なるアイデアとレポートがある。
When: 同じPC画面で案を切り替え、本文を縦にスクロールする。
Then: 星空画像と明暗の層は画面に固定され、背景の位置・寸法・切取り範囲と本文の表示幅が変わらない。本文だけをスクロールでき、グラフの光点と操作、サイドバー、保存値は変えない。

### US-23 星と名称の確実な選択

As a Nebulaの本人利用者, I want 星と名前を一回のクリックで選ぶ, so that 関連する記録を取りこぼさず探索できる。
Given: 物理配置済みの星と名称がある。
When: 星または名称を押し、押下中の移動が5 CSS px以内で離す。
Then: 押した位置の記録が一回だけ選択され、関連線が強調される。5px超のドラッグは選択しない。名称は画面内の8方向の空き位置から配置し、有効な配置を維持する。選択・ホバー時は全文へ到達できる。出典は安全なURLだけを新タブへ一回開く。保存データと星の位置・拡大率は変更しない。
