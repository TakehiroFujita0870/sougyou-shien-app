## 現況と訂正

- 接続・Neo4j保存・スマホからの書込み・アセット表示・画面遷移修正・ログオン起動・初回検索・非公開接続・既存速度比較は成功記録を維持する。同範囲の新しい故障が再現しない限り再課題化しない。
- #294/#295で既存成果のmain取り込みは完了。現在のサービスは`dots-live`から稼働している。この場所名だけで利用者機能が未反映だと判断しない。正式版との差はファイル内容・実行経路・実DB設定で判定する。
- 内容比較では現行のホーム画面・ローカル管理コードと配信UIはmainと一致。一方、稼働場所のstdio概要保存コードは独自永続化、mainはcanonical保存境界へ委譲する実装で差がある。稼働中の接続がどの経路を使うかは別に照合し、この差をURL欠落の原因と断定しない。画面の再移行を独立課題にしない。
- 2026-09-27の通常保存先の限定読取りでは、利用者がURL欠落を報告した1件に概要revision 1、調査Run参照0、全8章のClaim/Evidence参照0、該当意味関係0を確認した。本人は外部情報を取り込んだ調査を実施したと明示。保存上の未調査と実際の未調査を同一視せず、調査結果の取り込み欠落として扱う。個人の題名・ID・本文・URLはこの文書へ転載しない。欠落した操作と元のURLの所在はまだ特定していない。
- ホームの概要投影は章の本文だけを返し、根拠参照と出典一覧を返していない。本文にURLがなければUIから出典を確認できない。保存だけでなく読取り・表示も対象にする。
- 出典保存、調査Run記録、概要保存は別操作。Runへ出典を記載しただけではSource/Evidenceを作らず、概要取得も現状ではURLを返さない。概要の保存境界で根拠の実在・所有者・現行性・資料系譜を照合する検査を追加する。
- 関係登録MCPは新規の提案・推定を保存できるが、旧関係を置き換える指定は受け付けない。capture skillの改訂案内との不一致を修正する。本人の整理承認を新設する旧提案は撤回する。
- 分類の型と読取り基盤はある。ChatGPTによる分類作成・変更・階層検索の操作が揃っているとは扱わない。
- 自己紹介専用編集はあるが、全Asset共通の編集ではない。名前が「自己紹介」の記録も通常Assetとして一覧に含め、個別の自己紹介欄は廃止する。

## 会話と保存の流れ

1. 同じChatGPTが新しい具体的アイデア・資産を検知し、既存記録を照合して下書き保存する。一般論・雑談を記録にしない。
2. Dots内で類似案・能力・経験・資料を検索する。未調査案は保存・検索できるが、外部検証済みと表示しない。
3. 未調査の新しいIdeaを保存した会話では、内部検索の結果を添えて一度だけ調査を提案する。断った同じ案に同じ提案を反復しない。
4. 目的・範囲・試行回数の許諾を受けて同じChatGPTが外部調査する。通常のWeb検索とDeep Researchのどちらも同じ出典・根拠保存契約を使う。追加調査も許諾の残予算内で実行し、範囲・予算を超える場合は再許諾する。
5. 実際に使用した出典URL・題名・参照日・要約と、支える判断を保存する。調査済み概要は完了した調査Runと8観点に結び付ける。ユーザー自身の発言は本人申告として扱い、架空の外部URLを補わない。
6. 同じChatGPTが出典と正式概要の保存後、意味関係・分類を自動で整理する。追加のグラフ更新確認はしない。調査前の一時仮説は正式関係として固定しない。
7. 事実・本人申告・推測・未確認を区別する。自動整理の許可は、推測を確定事実へ昇格させる許可ではない。
8. 追加調査・本人の訂正・Asset編集で現在の内容を更新し、影響する意味関係・分類を再評価する。旧版は履歴として保持し、通常検索に混ぜない。
9. 次の会話は最新記録・意味関係・分類と根拠を再検索し、過去の資産を使った提案を返す。人間へノード・エッジ・内部IDの指定を要求しない。

下書き保存、調査済み概要保存、意味整理完了は別の状態として記録する。整理だけが失敗しても概要・出典を失わず、保存結果に未整理を返して再試行できるようにする。再送は同じ結果を二重保存しない。

公開資料の題名・URL・参照日・引用用短文は、許諾された調査で使った公開の根拠としてChatGPTへ再取得できる保存契約にする。人物の連絡先・非公開URL・資料本文をこの変更で共有可へ広げない。現行`capture_source`のローカル専用設定を無視して返すのではなく、共有するメタデータと本文の境界を操作・保存・取得のすべてで一致させる。

既存の欠落案も修復対象。元会話に残る実際の出典を回収できれば、同じIdeaへ根拠と改訂概要を紐付ける。元URLを取得できない場合はその不足を示し、本人へ元会話のURLまたは引用一覧だけを依頼する。新しい出典を元の調査で使ったと偽って付けず、同じ事業のフル調査を無断で繰り返さない。

## ユーザーストーリーと受け入れ条件

### US-1 出典と概要を次の会話で使う

As a 創業者, I want 調査で使用した出典を概要から開く, so that 判断の根拠を後から確かめられる。
Given: 通常のWeb検索またはDeep ResearchでChatGPTが公開資料を1件以上使用した調査結果と既存Ideaがある。
When: ChatGPTが調査Run・出典・8観点の概要を保存し、別会話とPC画面から取得する。
Then: 各判断の出典は保存時と同じURL・題名として取得できる。出典不足を調査済み完了と偽らず、失敗箇所を示す。未調査の本人発案へ架空のURLを付けない。

### US-2 意味関係を意識せず自動整理する

As a 創業者, I want 出典保存後に自分の資産とアイデアが自動で結び付く, so that 別会話で組み合わせを考えられる。
Given: 最新の調査済み概要、共有可能な根拠、既存Assetがある。
When: 同じChatGPTが出典と概要の保存に続いて内容を整理する。
Then: グラフ更新確認を追加せず、顧客課題・使える資産・不足能力・過去案への意味関係を根拠付きで保存する。保存履歴の接続を代用品としない。各関係にはその判断を支える根拠だけを使い、同じ章の無関係な根拠を一括流用しない。

### US-3 訂正後の判断を使う

As a 創業者, I want 会話で間違いを直す, so that 古い判断が後の提案へ混入しない。
Given: 有効な意味関係・分類と、それを変更する新しい概要または本人の訂正がある。
When: ChatGPTが旧記録を指定して置換または撤回し、同じ要求を再送する。
Then: 旧記録と根拠は履歴に残り、別会話の通常検索・グラフは新しい判断だけを現行として使う。再送で二重版を作らず、別所有者の記録や競合する更新を拒否する。

### US-4 アセットを一つの画面で編集する

As a 創業者, I want 全アセットを単純な一覧で編集する, so that 個別の区分や分類作業を管理しなくてよい。
Given: 自己紹介という名前のAssetと、能力・経験・知識・資料のAssetがある。
When: 1280×720の「あなたのアセット」を開き、一つの記録の題名・内容を編集する。
Then: 「自己紹介」「保有している資産」の表示・専用欄とカテゴリー分けがなく、全Assetが同じカード形式で並ぶ。保存後の再読込みで更新が残り、失敗時は入力が残る。別経路で更新された記録の上書きを防ぎ、旧版の重複表示をしない。既存の内容は削除しない。

### US-5 画面編集の共有範囲を保つ

As a 創業者, I want 編集した情報の共有範囲を確認する, so that ChatGPTで使う情報と非公開メモを混同しない。
Given: 共有可とローカル専用のAssetがある。
When: 画面から題名・内容を編集する。
Then: 現在の共有設定を保持し、共有可の最新版はChatGPTから再取得でき、ローカル専用の内容は返らない。共有範囲を広げる操作は本人の明示操作で行い、編集だけで自動公開しない。

### US-6 分類から具体案と資産を探す

As a 創業者, I want 広い領域から具体案へ絞り込む, so that 言い回しが違う過去案や資産も発見できる。
Given: 業界・顧客課題・能力の複数分類と、複数の分類に属するIdea/Assetがある。
When: ChatGPTが分類を検索し、親分類から子分類と具体記録へ進む。
Then: 根拠付きの分類と現行記録を取得でき、循環を保存せず、未分類記録を検索から落とさない。グラフ画面の奥行き移動で分類に対応する領域へ進める。

### US-7 正本だけを使う

As a 創業者, I want ツール一覧から正本Dotsだけを選ぶ, so that 試験接続へ誤保存しない。
Given: 正本と検証用の接続、および旧画面のコードが存在する。

### US-8 調査を自然に提案する

As a 創業者, I want 新しいIdeaに調査の提案を受ける, so that 保存で会話が終わらない。

Then: 新しい差分だけを反映し、変更した機能を確認する。場所名や古いチェック欄だけを理由に再移行・PC再起動・速度比較を要求しない。実装・検査・main反映・稼働反映を分けて現況へ記録する。

## 画面の確定仕様

- ホーム: アイデア／あなたのアセット／人的ネットワークの3タブ。
- アイデア: カード一覧と8観点の概要。引用がある章は出典題名とURLを開ける。全レポート本文の保存・編集画面は追加しない。
- あなたのアセット: 全Assetを同じカードで表示。「自己紹介」「あなたについて」「保有している資産」の表示と専用編集を廃止。カテゴリー・分類見出し・分類操作は置かず、題名・内容だけを編集できる。内容は保持し、内部の分類はこの画面へ露出しない。
- 人的ネットワーク: 「今後実装予定」を維持。
- グラフ: データの意味関係と分類を既存の3D描画へ渡す。保存履歴は内部根拠として保持するが意味関係の代用品にしない。Ideas/Assets/Sources/Peopleのページ内タブを復活させない。
- サービス管理: 現在の起動・停止・状態表示を保持。新しい管理基盤を増やさない。
- 画面監査はPC1280×720のみ。スマートフォンのChatGPT接続と、Dotsのスマートフォン用画面は別扱い。

## ADR

| 判断 | 選択と理由 | 却下案と理由 | 結果 |
| --- | --- | --- | --- |
| 整理の主体 | 対話中のChatGPTがMCPを使う。利用者が別AIを管理しない | 別LLM常駐抽出・別調査scheduler。責務と費用を増やす | 新しい外部AI接続なし |
| 自動更新 | 出典・正式概要保存後、承認なしで意味関係・分類を保存。再送・根拠・共有制約は保持 | 関係ごとの確認。利用者の最新意思に反する | 調査許諾と共有拡大の確認は残す |
| アセットの形 | 自己紹介も通常Assetの一つ。全カード同じ編集契約 | 自己紹介本文と分割Assetの二重管理。同期負担を増やす | 自己紹介の強制再合成は実装しない |
| アセットの表示 | カテゴリーなしの共通一覧。題名・内容を編集 | 初期カテゴリーと手作業の分類。利用者が撤回した | 内部の抽象分類をUIの分類欄と混同しない |
| 抽象分類 | 業界・顧客課題・能力を複数軸にし、複数所属を許す。親子関係は循環禁止 | 一本の固定ツリー。複数領域に属する案を落とす | 広い領域→具体記録と横断検索の両方を保持 |
| 根拠の粒度 | 各関係が表す判断に対応する出典/本人申告を指定する | 章の全Evidenceを無条件で使う。無関係な根拠を付ける | 事実と推測を区別する |
| 正式版の反映 | 新機能の配送に必要な差分だけ反映。実DB設定を照合 | main取り込みの再実行や、場所を変えること自体を完成条件にする。土台確認が循環する | 独立した大規模移行を作らない |
| 旧資産の削除 | 未使用群単位、Gitから復元可能、実データを保持 | 全旧ディレクトリの一括削除。現行依存とデータを失う | 整理は優先2番目 |
| 検索モデル | 現行E5-base/mMARCOの固定版を継続 | 新モデル選定・速度比較。今回の欠落に関係しない | 比較の再実施なし |

## スコープ外

- 人的ネットワーク・名刺の登録画面、本格的な人物管理。
- スマートフォン用UI、複数利用者、課金、一般公開、PC停止中の常時接続。
- 追加のEmbedding/リランカー選定と速度比較、全体ベンチマークの反復。
- 別AIインスタンス、Dots独自調査scheduler、通知基盤、調査レポートの製本保管。
- 既存成功の起動・画面遷移・本人限定設定・backup/restoreを再証明するためだけの操作。
- データ・鍵・DB volume・モデルキャッシュの削除。`docs/inherited/`の変更。
- 立体描画の新規選定、装飾の作り込み、3Dだけのための追加DB。

## 配送・検査・戻し方

独立PRは必要な意味単位に限定し、各変更に受入条件・検査・戻し方を記録する。文書変更だけなら計画の整合性・文字化け・進捗validator・差分検査を実施し、製品の実会話試験や速度比較を追加しない。製品変更は対象の単体/保存/UI検査と必須CIを通し、同一会話の独立レビュー後にmainへ反映する。

サービス反映は現在の安定場所を維持できる。DB設定変更が不要なら構造移行をしない。設定差がある場合だけ対象索引/制約を列挙し、通常データを失わない手順と戻し方を先に用意する。未知の差は移行番号だけで処理しない。

各配送後に現況一覧の4軸を更新する。文書のmergeだけで稼働済みと記録しない。APIの破壊的変更・公開・支出・共有拡大の未許諾があれば当該操作だけ止める。プラグイン解除は通常データの削除ではなく、正本の登録内容を保持して復帰手順を記録する。

## 完成条件

- US-1～US-9の観測結果が記録され、実装・検査・main・稼働の混同がない。
- 未調査案は下書きで保存・検索でき、URLを捏造しない。外部資料を使った概要は出典を取得・表示できる。
- 自動整理された意味関係と分類を別会話で使え、訂正後の検索が旧判断を現行として返さない。
- 全Assetが同一画面・同一編集経路にあり、共有範囲と履歴を保持する。
- 検証用接続が利用者の一覧からなく、正本Dotsと通常データが残る。
- 人的ネットワーク・装飾・クラウド常時稼働を完成待ちの理由にしない。
