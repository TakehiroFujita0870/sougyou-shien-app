# アセットの履歴付き編集契約

最終検証日: 2026-09-27

対象: 残実装計画A-1 / US-4、US-5。カテゴリーや自己紹介専用欄は追加しない。

- Assetの初版はrevision 1、supersedes_idなし。旧形式の保存内容もこの既定値で読む。
- 題名・内容の更新は旧版を消さず、新しいIDと次のrevisionを持つ後継版を作る。
- 所有者、種類、共有範囲、既存detailsは変えない。画面編集だけで共有を拡大しない。
- 一般の作成操作から後継版を保存することは禁止する。専用の更新境界だけを使う。
- Assetの初版規律を、既存Ideaのrevision 0形式へ流用しない。以前に保存したIdeaと根拠付き関係は読める状態を保つ。
- PersonAssetの安全な取得結果でも内部の版番号を正しく返す。人物の連絡先や非公開メモは公開項目へ追加しない。
- 更新境界は現在の版と期待revisionを照合する。古い入力は競合として拒否する。
- 同じ要求と同じ再送キーは同じ結果を返す。内容を変えて同じキーを使うことは拒否する。
- 親の欠落、循環、分岐、版の飛び、種類・共有範囲・detailsの変化は拒否する。
- 通常の取得・検索は現行版だけを返す。旧版を参照する関係は無条件で新しい内容の根拠へ引き継がない。
- 保存IDの衝突時は既存記録を上書きせず、監査記録の保存失敗時は新しい版を残さない。

配送はメモリ保存と共通モデル、Neo4j保存・取得、画面と編集経路へ分ける。最初の配送だけでは利用者向け編集機能を完成と扱わない。

最初の受入検査: `test_asset_revision_write.py`で共有保持、再送、競合、他の所有者、現行版検索、壊れた履歴、作成境界、details一致、ID衝突、監査失敗の巻戻しを確認する。

差し戻し記録: 全体検査で旧Ideaのrevision 0を誤って非現行扱いする回帰とPersonAssetの版投影不一致を検出した。計画を上記の既存形式保持と安全な投影へ明確化してから修正し、根拠付き関係の取得・両保存方式の投影一致を全体検査へ含める。

戻し方: 当該コード変更をGitの記録から戻す。既存データ・鍵の削除や破壊的DB移行は行わない。後継版の作成開始後は読み取り側も同時に戻し、旧版を現行と取り違えないよう確認する。
