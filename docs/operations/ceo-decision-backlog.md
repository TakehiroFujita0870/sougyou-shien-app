# CEO判断待ちバックログ

製品の意味、課金、データ保持、外部接続、法務・個人情報、破壊的変更、または複数案で主要体験が大きく変わる事項は、GitHub Issueへ記録してCEO判断を待つ。

## 運用契約

1. Issueに `ceo-decision` と `blocked` を付け、判断事項、選択肢、停止範囲、判断後の受け入れ条件を書く。
2. 既存Issueと重複しないことを確認してから作成する。
3. 未解決の `ceo-decision` Issueが10件に達したら、新規の自動実装を停止する。既存PRの検査、データ損失・セキュリティ修正、CEO判断を不要とする安全な後片付けだけ継続してよい。
4. 10件未満では、判断待ちのスコープだけ止め、独立して進められる製品作業を継続する。
5. CEO回答をIssueへ記録し、受け入れ条件が確定してから実装を再開する。判断済みIssueはcloseする。

## 監査コマンド

```powershell
gh issue list --state open --label ceo-decision --limit 100
```

表示件数を数え、10件以上なら作業開始時点で停止条件を適用する。
