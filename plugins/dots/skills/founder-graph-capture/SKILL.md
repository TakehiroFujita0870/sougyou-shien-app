# Dotsへの自然な記録

この手順は、現在のメッセージでDotsが利用可能で、利用者が自分の創業活動について新しい具体的な内容を話した場合に使う。一般論の質問、単なる雑談、第三者の噂だけでは記録を増やさない。Dotsを選んでいないメッセージでDotsへ保存したと主張しない。

1. 保存候補の種類（アイデア、資産、人物、判断など）を見極め、Dots内で関連する既存記録を検索する。既存の同一記録があれば重複作成せず、その記録を再利用する。類似するだけで同一とは断定しない。
2. 新しい具体的な内容なら、明示的な「保存して」がなくても該当するDotsの記録機能を使う。Ideaは未調査の下書きとして保存・検索できる。創業者がすでに持ち別案でも再利用できる質問票・資料・能力は`capture_asset`で独立したAssetを作り、Ideaの説明へ混ぜるだけで終えない。その場で考えた質問や分析観点を、実在するAssetとして捏造しない。下書き段階ではIdeaの正式な意味関係を`link_entities`で作らず、候補を会話や下書きに留める。
3. 通常用のDotsでは、後のChatGPT会話で再検索できるよう、創業者が会話で共有した新しいIdeaの短い題名・要約は、機微情報を含まない場合に`shareable`で保存する。会話原文はローカルに留まり、人物の連絡先・非公開メモ・資料本文は回答へ出さない。機微情報を含むIdeaや人物・資料の記録は`local_only`を保ち、再検索できないことを必要に応じて伝える。接続先が架空データ専用の場合、実在人物や実際の非公開情報は書き込まない。曖昧な同一人物の統合、削除、外部への共有は通常の記録と別に扱う。
4. 再試行では同じ内容に同じ重複防止キーを使い、成功した記録のIDを次の関係づけや検索に渡す。保存済みと言うのは書込み結果を受け取ってから。検索だけだった場合や接続に失敗した場合は、その事実を簡潔に伝える。
5. フル調査の前にDots内の既存アイデア・資産・根拠を検索し、類似する内容を掘り下げる。調査を勧める場合は`create_research_campaign`で目的・対象Idea・範囲・試行予算・期限を未許諾で保存し、返された提案を利用者へ示す。明示許諾を受けた後だけ`approve_research_campaign`を呼ぶ。保存やこのスキルの自動選択は調査の許諾ではない。これらの操作は調査自体を実行しない。
6. 外部調査はChatGPT側で行う。開始前に現在の許諾・残試行数・期限を確認し、返された許諾snapshotとrevisionを使う。開始・終了時刻を記録し、終端結果を`record_research_run`へ渡す。同じ結果の再送だけ同じ重複防止キーを使う。部分完了・失敗・中止をcompletedと偽らない。追加試行は許諾の範囲と残予算内に限り、変更や超過は新たな許諾を得る。利用者が許諾を取り消した場合は`revoke_research_campaign`で取消を記録し、以後の調査を進めない。期限切れにも進めず、取消操作自体が実行中の外部処理を停止するとは保証しない。
7. 調査が完了したら、0.エグゼクティブサマリー、1.ビジネスモデル、2.顧客とマーケットサイズ、3.収益モデル、4.競争優位性、5.実現可能性、6.リスク・撤退ライン、7.リスクミニマムなロードマップを整理する。引用元を保存し、存在する資料・Claim・EvidenceのIDを章に紐付け、完了RunのIDと全8観点を`save_researched_idea_brief`へ渡す。未調査・部分概要は`save_idea_brief`を使い、調査済みとは呼ばない。
8. 正式保存の成功後、最新概要を`fetch_idea_brief`で取得して内容から関係候補を抽出する。Ideaを含む`link_entities`には最新概要ID、根拠の章番号、その章から返された共有可能なEvidence IDを渡す。根拠が取得できなければ関係を作らず、捏造しない。事実と推測を区別し、原則proposedかinferredとして保存する。Idea→Assetの再利用は`REUSES`、必要な能力は`REQUIRES_CAPABILITY`を使う。`BASED_ON`はIdea→Assetには使わない。
9. 追加調査・概要改訂後は新しい概要版を保存し、関係を再評価する。変更対象が変わる場合も旧関係IDを`supersedes_id`として明示し、削除や重複作成で訂正を表現しない。次の会話ではDotsを再検索し、現在の関係と返された根拠を使って組合せを提案する。期限・根拠・関係のIDを推測で補わない。該当機能が接続に無ければ操作を試作せず、未反映であることを伝える。
