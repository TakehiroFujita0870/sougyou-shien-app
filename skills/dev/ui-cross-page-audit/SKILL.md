# UI横断監査

## 適用と境界

画面変更前に読み、実装後に同じ役割の部品をページ間で比較する。別解像度やスマートフォンの確認を追加しない。画面の製品境界は[製品方針](../../../docs/plans/founder-graph-pivot.md)、実際の尺度は現行の3画面で照合する。監査だけでは実データの編集・削除を許可しない。

## 実装前

- ホームの3タブ、グラフ、サービス管理を1280×720で確認する。ブラウザー操作前にcomputer-useスキルを読む。データ準備と状態取得にはCLI/APIを優先する。
- 対応する部品の尺度を比較する: ナビ、カード題名、本文、補足、状態、編集操作。差が意味によるものか、不揃いかを判断する。
- 対象計画へ修正箇所を記録する。スクリーンショット専用の新しい台帳を作らない。

## 実装後の確認

1. 同じ役割の文字サイズ・太さ・行間・余白・アイコン線幅がページ間で一致する。意図した例外は理由がある。
2. 通常文字のコントラスト4.5:1、操作の識別3:1を確認する。星空の明るい部分でも読めるカード背景にする。色だけで選択や状態を示さない。
3. 長い日本語題名、本文、空一覧で見切れや重なりがない。省略した内容へ到達できる。状態バッジは題名と共存する。
4. 小さなペン・ゴミ箱は32×32px以上の操作範囲、説明名、フォーカスを持つ。アイコン操作が親カードの選択を誤発火しない。
5. 編集、キャンセル、保存失敗で入力を失わない。削除確認には対象名があり、復元へ到達できる。検査は合成fixtureを使う。
6. ホーム→グラフ→サービス管理→ホームを移動し、白画面・二重スクロール・描画の残留がない。奥行き操作と根拠表示を壊していない。

## 完了判定

計画のUI条件を満たす実画面と影響範囲の自動検査を確認する。画像だけで操作合格にしない。確認不能は未検証と記す。同じ変更版の合格を反復せず、関連コードが変わった箇所だけ再確認する。

ユーザーの指示を守ったことの説明を製品画面へ入れない。監査結果は計画またはPRに短く残す。新たなUI方針が必要なら実装で勝手に決めず、その範囲を判断待ちにする。
